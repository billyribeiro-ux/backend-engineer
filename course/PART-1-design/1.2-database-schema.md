# Lesson 1.2 — The Database Schema (Single Tenant)

## From Diagram to SQL

This lesson translates everything from Lesson 1.1 into actual SQL. We're using **PostgreSQL** — the most capable open-source relational database and the industry standard for serious backend systems.

Read through each table carefully. Every column name, type, and constraint is a deliberate decision. The comments explain the why.

We'll build the full single-tenant schema here. Multi-tenancy (adding `organization_id`) comes in Part 7.

---

## Key Concepts Before We Start

**UUID vs Auto-Increment Integer**

Most tutorials use `id SERIAL` (auto-increment: 1, 2, 3...). We use `id UUID` instead.

Why? Because:
- Sequential IDs reveal information (`user/1001` tells an attacker there are ~1000 users)
- Sequential IDs cause problems when merging databases or sharding
- UUIDs are globally unique — safe to generate on any server without coordination

We'll use UUID v4 (random) for most IDs.

**`NOT NULL` vs nullable columns**

A column is `NOT NULL` when a row can never exist without that value.
A column is nullable (no constraint) when it might not have a value yet.

Example: `deleted_at` is nullable — it's NULL until the row is soft-deleted.

**Soft Delete**

Instead of `DELETE FROM users WHERE id = '...'`, we set `deleted_at = NOW()`.
The row still exists. Queries that show "active" records filter with `WHERE deleted_at IS NULL`.

This preserves history, protects billing integrity, and makes recovery possible.

## The Full Schema

```sql
-- Extensions
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";  -- generates UUIDs


-- ============================================================
-- ORGANIZATIONS (multi-tenancy — added in Part 7, scaffolded here)
-- ============================================================
CREATE TABLE organizations (
  id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name            TEXT NOT NULL,
  slug            TEXT NOT NULL UNIQUE,  -- URL-safe identifier e.g. 'acme-corp'
  stripe_customer_id TEXT UNIQUE,        -- Stripe customer for org-level billing
  is_active       BOOLEAN NOT NULL DEFAULT true,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at      TIMESTAMPTZ
);


-- ============================================================
-- USERS
-- ============================================================
CREATE TABLE users (
  id                    UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  email                 TEXT NOT NULL UNIQUE,
  password_hash         TEXT NOT NULL,           -- bcrypt hash, never plain text
  display_name          TEXT,
  stripe_customer_id    TEXT UNIQUE,             -- Stripe's customer ID for this user
  email_verified_at     TIMESTAMPTZ,             -- NULL = not yet verified
  last_login_at         TIMESTAMPTZ,
  organization_id       UUID REFERENCES organizations(id),  -- primary org
  created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at            TIMESTAMPTZ
);

CREATE INDEX idx_users_email ON users(email) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_organization_id ON users(organization_id);


-- ============================================================
-- ROLES & PERMISSIONS (RBAC)
-- ============================================================
CREATE TABLE roles (
  id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name        TEXT NOT NULL UNIQUE,   -- 'admin', 'member', 'guest', 'support'
  description TEXT,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE permissions (
  id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name        TEXT NOT NULL UNIQUE,   -- 'products:write', 'subscriptions:manage', etc.
  description TEXT,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE role_permissions (
  role_id       UUID NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
  permission_id UUID NOT NULL REFERENCES permissions(id) ON DELETE CASCADE,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (role_id, permission_id)
);

-- Users can have roles, and a role can apply to many users
-- The role lives per organization membership (see organization_members below)
CREATE TABLE user_roles (
  user_id    UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role_id    UUID NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (user_id, role_id)
);

-- When multi-tenancy is added, we'll also have organization_members
-- which stores role per user per org. user_roles handles the global/platform level.


-- ============================================================
-- PRODUCTS
-- ============================================================
CREATE TABLE products (
  id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name        TEXT NOT NULL,
  description TEXT,
  is_active   BOOLEAN NOT NULL DEFAULT true,
  stripe_product_id TEXT UNIQUE,     -- Stripe's product ID
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at  TIMESTAMPTZ
);


-- ============================================================
-- SUBSCRIPTION PLANS
-- ============================================================
CREATE TABLE plans (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name             TEXT NOT NULL,              -- 'Monthly', 'Quarterly', 'Yearly'
  interval         TEXT NOT NULL,              -- 'month', 'year'
  interval_count   INTEGER NOT NULL DEFAULT 1, -- 1 month, 3 months, 12 months
  is_active        BOOLEAN NOT NULL DEFAULT true,
  stripe_product_id TEXT UNIQUE,               -- Stripe product for this plan
  created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at       TIMESTAMPTZ,
  CONSTRAINT valid_interval CHECK (interval IN ('day', 'week', 'month', 'year')),
  CONSTRAINT positive_interval_count CHECK (interval_count > 0)
);


-- ============================================================
-- PRICES
-- ============================================================
-- Critical: prices are never updated. New price = new row.
-- This preserves price history for grandfathering.
CREATE TABLE prices (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  -- Either product_id OR plan_id, never both, never neither
  product_id       UUID REFERENCES products(id),
  plan_id          UUID REFERENCES plans(id),
  amount_cents     INTEGER NOT NULL,           -- $29.99 = 2999
  currency         TEXT NOT NULL DEFAULT 'usd',
  applies_to       TEXT NOT NULL DEFAULT 'future_members',
  applies_from_date DATE,                      -- only used when applies_to = 'from_date'
  stripe_price_id  TEXT UNIQUE,                -- Stripe's price ID
  is_current       BOOLEAN NOT NULL DEFAULT true,  -- only one current price per product/plan
  created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT valid_applies_to CHECK (
    applies_to IN ('future_members', 'all_members', 'from_date')
  ),
  CONSTRAINT positive_amount CHECK (amount_cents >= 0),
  CONSTRAINT price_belongs_to_one CHECK (
    (product_id IS NOT NULL AND plan_id IS NULL) OR
    (product_id IS NULL AND plan_id IS NOT NULL)
  ),
  CONSTRAINT from_date_requires_date CHECK (
    applies_to != 'from_date' OR applies_from_date IS NOT NULL
  )
);

CREATE INDEX idx_prices_product_id ON prices(product_id) WHERE product_id IS NOT NULL;
CREATE INDEX idx_prices_plan_id ON prices(plan_id) WHERE plan_id IS NOT NULL;
CREATE INDEX idx_prices_current ON prices(is_current) WHERE is_current = true;


-- ============================================================
-- SUBSCRIPTIONS
-- ============================================================
CREATE TABLE subscriptions (
  id                     UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id                UUID NOT NULL REFERENCES users(id),
  plan_id                UUID NOT NULL REFERENCES plans(id),
  locked_price_id        UUID REFERENCES prices(id),  -- grandfathered price
  stripe_subscription_id TEXT UNIQUE NOT NULL,
  status                 TEXT NOT NULL DEFAULT 'trialing',
  -- Status mirrors Stripe: 'trialing', 'active', 'past_due', 'canceled', 'unpaid', 'incomplete'
  trial_ends_at          TIMESTAMPTZ,
  current_period_start   TIMESTAMPTZ,
  current_period_end     TIMESTAMPTZ,
  cancel_at_period_end   BOOLEAN NOT NULL DEFAULT false,
  canceled_at            TIMESTAMPTZ,
  created_at             TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at             TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at             TIMESTAMPTZ,
  CONSTRAINT valid_status CHECK (
    status IN ('trialing', 'active', 'past_due', 'canceled', 'unpaid', 'incomplete', 'incomplete_expired')
  )
);

CREATE INDEX idx_subscriptions_user_id ON subscriptions(user_id);
CREATE INDEX idx_subscriptions_status ON subscriptions(status) WHERE deleted_at IS NULL;


-- ============================================================
-- INVOICES
-- ============================================================
CREATE TABLE invoices (
  id                 UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id            UUID NOT NULL REFERENCES users(id),
  subscription_id    UUID REFERENCES subscriptions(id),  -- NULL for one-time purchases
  stripe_invoice_id  TEXT UNIQUE,
  amount_cents       INTEGER NOT NULL,
  currency           TEXT NOT NULL DEFAULT 'usd',
  status             TEXT NOT NULL DEFAULT 'open',
  -- 'draft', 'open', 'paid', 'uncollectible', 'void'
  paid_at            TIMESTAMPTZ,
  due_date           TIMESTAMPTZ,
  created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT valid_invoice_status CHECK (
    status IN ('draft', 'open', 'paid', 'uncollectible', 'void')
  )
);

CREATE INDEX idx_invoices_user_id ON invoices(user_id);
CREATE INDEX idx_invoices_subscription_id ON invoices(subscription_id);


-- ============================================================
-- PAYMENTS
-- ============================================================
CREATE TABLE payments (
  id                       UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id                  UUID NOT NULL REFERENCES users(id),
  invoice_id               UUID REFERENCES invoices(id),
  product_id               UUID REFERENCES products(id),  -- for one-time purchases
  stripe_payment_intent_id TEXT UNIQUE NOT NULL,
  amount_cents             INTEGER NOT NULL,
  currency                 TEXT NOT NULL DEFAULT 'usd',
  status                   TEXT NOT NULL,
  -- 'pending', 'succeeded', 'failed', 'canceled', 'refunded'
  idempotency_key          TEXT UNIQUE NOT NULL,   -- prevents double-processing
  refunded_at              TIMESTAMPTZ,
  created_at               TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at               TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT valid_payment_status CHECK (
    status IN ('pending', 'succeeded', 'failed', 'canceled', 'refunded')
  )
);

CREATE INDEX idx_payments_user_id ON payments(user_id);


-- ============================================================
-- COUPONS
-- ============================================================
CREATE TABLE coupons (
  id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  code            TEXT NOT NULL UNIQUE,          -- the promo code users type in
  discount_type   TEXT NOT NULL,                 -- 'percent' or 'fixed'
  discount_value  INTEGER NOT NULL,              -- percent: 0-100, fixed: cents
  max_uses        INTEGER,                       -- NULL = unlimited
  current_uses    INTEGER NOT NULL DEFAULT 0,
  expires_at      TIMESTAMPTZ,                   -- NULL = never expires
  applies_to      TEXT NOT NULL DEFAULT 'all',   -- 'all', 'products', 'plans'
  stripe_coupon_id TEXT UNIQUE,
  is_active       BOOLEAN NOT NULL DEFAULT true,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT valid_discount_type CHECK (discount_type IN ('percent', 'fixed')),
  CONSTRAINT valid_percent CHECK (
    discount_type != 'percent' OR (discount_value >= 0 AND discount_value <= 100)
  ),
  CONSTRAINT valid_applies_to CHECK (applies_to IN ('all', 'products', 'plans')),
  CONSTRAINT positive_discount CHECK (discount_value >= 0)
);

CREATE TABLE coupon_redemptions (
  id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  coupon_id   UUID NOT NULL REFERENCES coupons(id),
  user_id     UUID NOT NULL REFERENCES users(id),
  payment_id  UUID REFERENCES payments(id),
  used_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (coupon_id, user_id)  -- a user can only redeem each coupon once
);


-- ============================================================
-- WEBHOOK EVENTS
-- ============================================================
CREATE TABLE webhook_events (
  id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  stripe_event_id TEXT NOT NULL UNIQUE,    -- UNIQUE = idempotency guarantee
  event_type      TEXT NOT NULL,           -- 'invoice.paid', 'subscription.updated', etc.
  payload         JSONB NOT NULL,          -- full event body from Stripe
  processed_at    TIMESTAMPTZ,             -- NULL = not yet processed
  error           TEXT,                   -- if processing failed, what went wrong
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_webhook_events_stripe_id ON webhook_events(stripe_event_id);
CREATE INDEX idx_webhook_events_unprocessed ON webhook_events(created_at)
  WHERE processed_at IS NULL;


-- ============================================================
-- AUDIT LOGS
-- ============================================================
CREATE TABLE audit_logs (
  id            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  actor_id      UUID,                 -- user who did it (NULL for system actions)
  actor_type    TEXT NOT NULL DEFAULT 'user',  -- 'user', 'system', 'stripe'
  action        TEXT NOT NULL,        -- 'subscription.canceled', 'price.updated', etc.
  resource_type TEXT NOT NULL,        -- 'subscription', 'price', 'user', etc.
  resource_id   UUID,                 -- UUID of the affected record
  metadata      JSONB,                -- any additional context (old values, new values)
  ip_address    INET,                 -- for security audit trails
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
  -- No updated_at. No deleted_at. Audit logs are NEVER modified.
);

CREATE INDEX idx_audit_logs_actor_id ON audit_logs(actor_id);
CREATE INDEX idx_audit_logs_resource ON audit_logs(resource_type, resource_id);
CREATE INDEX idx_audit_logs_created_at ON audit_logs(created_at);
```

## The Constraints That Prevent Bad Data

Look at the `CHECK` constraints above. These are database-level rules — they fire before a row is inserted or updated.

Some highlights:

**`price_belongs_to_one`** — A price must belong to either a product or a plan, never both, never neither. Without this, you could insert a "floating" price not attached to anything.

**`from_date_requires_date`** — If `applies_to` is `'from_date'`, then `applies_from_date` must have a value. Without this, you could create a "from_date" price with no date, which is nonsensical.

**`UNIQUE (coupon_id, user_id)`** on `coupon_redemptions` — A user can only redeem a specific coupon once. This is enforced at the database level, not just in application code. Database-level constraints are your last line of defense.

**`stripe_event_id TEXT NOT NULL UNIQUE`** on `webhook_events` — This is the entire idempotency guarantee for Stripe webhooks. If you try to insert the same event twice, the database refuses. The duplicate check in code is a fast path; this constraint is the guarantee.

---

## Why PostgreSQL `CHECK` Constraints Beat Application Validation

Application code can have bugs. Network issues can cause partial writes. Background jobs can bypass your API. Direct database access during debugging can skip your validation.

Database constraints cannot be bypassed. They fire on every write, no matter where it comes from. They're your last line of defense, and they should cover every rule that must never be violated.
