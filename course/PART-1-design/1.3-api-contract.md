# Lesson 1.3 — API Contract Design

## What Is an API Contract?

An API (Application Programming Interface) is the layer between your backend and the outside world. It's how mobile apps, web browsers, and other services talk to your system.

A **contract** is the agreed-upon format for that conversation: what can you ask for, how do you ask for it, and what will you get back?

Designing the contract before writing handlers is critical because:
1. Frontend developers can build against a documented contract without waiting for the backend
2. You catch design inconsistencies before they're in code
3. You discover missing endpoints or missing data in responses before a sprint is done

---

## REST Conventions (Explained Without Jargon)

REST is the most common API style. It uses HTTP — the same protocol your browser uses — organized around resources.

**Resources** are the entities: users, products, subscriptions, etc.
**HTTP verbs** describe what you want to do with them:
- `GET` — read something
- `POST` — create something
- `PUT` / `PATCH` — update something (`PATCH` = partial update, `PUT` = full replacement)
- `DELETE` — delete something

**URL patterns:**
```
GET    /users           → list users
GET    /users/:id       → get one user
POST   /users           → create a user
PATCH  /users/:id       → update a user
DELETE /users/:id       → delete a user
```

The `:id` is a placeholder for the actual UUID.

**HTTP status codes** tell the client what happened:
- `200 OK` — success, here's your data
- `201 Created` — you created something, here it is
- `204 No Content` — success, nothing to return
- `400 Bad Request` — you sent invalid data
- `401 Unauthorized` — you're not logged in
- `403 Forbidden` — you're logged in but not allowed to do this
- `404 Not Found` — that resource doesn't exist
- `409 Conflict` — the action conflicts with existing state (e.g., duplicate email)
- `422 Unprocessable Entity` — data format is correct but semantically invalid
- `500 Internal Server Error` — something went wrong on our side

---

## The Standard Error Response Format

**Bad:**
```json
{ "error": "something went wrong" }
```

**Good:**
```json
{
  "error": {
    "code": "SUBSCRIPTION_ALREADY_ACTIVE",
    "message": "You already have an active subscription.",
    "field": null
  }
}
```

The `code` is a machine-readable string your frontend can switch on. The `message` is human-readable. The `field` (optional) tells which field caused a validation error.

This format is used on EVERY error response. No exceptions.

## The Full API Contract

### Base URL
`/api/v1`

All endpoints are prefixed with this. Versioning (`v1`) allows you to make breaking changes later by creating `/api/v2` without breaking existing clients.

---

### Auth Endpoints

```
POST /api/v1/auth/register
  Body: { email, password, display_name }
  Response 201: { user: { id, email, display_name }, access_token, refresh_token }
  Response 400: validation error
  Response 409: email already exists
  Auth: none (public)

POST /api/v1/auth/login
  Body: { email, password }
  Response 200: { user: { id, email, display_name, role }, access_token, refresh_token }
  Response 401: invalid credentials
  Auth: none (public)
  Rate limit: 5 attempts per 15 minutes per IP

POST /api/v1/auth/refresh
  Body: { refresh_token }
  Response 200: { access_token, refresh_token }
  Response 401: invalid or expired refresh token
  Auth: none (uses refresh token)

POST /api/v1/auth/logout
  Body: { refresh_token }
  Response 204
  Auth: authenticated (access token)

POST /api/v1/auth/verify-email
  Body: { token }
  Response 200: { message: "Email verified" }
  Response 400: invalid or expired token
  Auth: none (public)
```

### User Endpoints

```
GET /api/v1/users/me
  Response 200: { id, email, display_name, role, subscription, created_at }
  Auth: authenticated
  RBAC: any authenticated user
  ABAC: returns data for the requesting user only

PATCH /api/v1/users/me
  Body: { display_name? }
  Response 200: { id, email, display_name }
  Auth: authenticated
  RBAC: member, admin
  ABAC: user can only update their own profile

PATCH /api/v1/users/me/password
  Body: { current_password, new_password }
  Response 204
  Auth: authenticated

GET /api/v1/users
  Response 200: { users: [...], total, page, per_page }
  Auth: authenticated
  RBAC: admin, support
  ABAC: —
  Note: support agents see limited fields (no payment methods)

GET /api/v1/users/:id
  Response 200: { id, email, display_name, role, subscription, created_at }
  Auth: authenticated
  RBAC: admin, support
  ABAC: —

PATCH /api/v1/users/:id
  Body: { display_name?, role? }
  Response 200: { user }
  Auth: authenticated
  RBAC: admin only
  ABAC: cannot demote or modify the organization owner

DELETE /api/v1/users/:id
  Response 204 (soft delete)
  Auth: authenticated
  RBAC: admin only
  ABAC: cannot delete the organization owner or yourself
```

### Product Endpoints

```
GET /api/v1/products
  Response 200: { products: [{ id, name, description, current_price, is_active }] }
  Auth: none (public)
  Note: includes only the current price for each product

GET /api/v1/products/:id
  Response 200: { id, name, description, current_price, is_active }
  Auth: none (public)

POST /api/v1/products
  Body: { name, description, amount_cents, currency }
  Response 201: { product, price }
  Auth: authenticated
  RBAC: admin only

PATCH /api/v1/products/:id
  Body: { name?, description?, is_active? }
  Response 200: { product }
  Auth: authenticated
  RBAC: admin only
  Note: does NOT update price — use the price endpoint for that

POST /api/v1/products/:id/prices
  Body: { amount_cents, currency, applies_to, applies_from_date? }
  Response 201: { price }
  Auth: authenticated
  RBAC: admin only
  Note: creates a new price record (never overwrites old price)

GET /api/v1/products/:id/prices
  Response 200: { prices: [...] }  -- full price history
  Auth: authenticated
  RBAC: admin only
```

### Subscription Endpoints

```
POST /api/v1/subscriptions
  Body: { plan_id, coupon_code?, payment_method_id }
  Response 201: { subscription, client_secret? }
  Auth: authenticated
  RBAC: member
  ABAC: user cannot have more than one active subscription

GET /api/v1/subscriptions/me
  Response 200: { subscription: { id, plan, status, current_period_end, price } }
  Auth: authenticated
  RBAC: any authenticated user
  ABAC: returns only the requesting user's subscription

PATCH /api/v1/subscriptions/me/cancel
  Body: { immediately? }  -- default: cancel at period end
  Response 200: { subscription }
  Auth: authenticated
  RBAC: member
  ABAC: only the subscription owner

PATCH /api/v1/subscriptions/me/resume
  Response 200: { subscription }
  Auth: authenticated
  RBAC: member
  ABAC: only the subscription owner
  Note: only valid if cancel_at_period_end = true and period hasn't ended

GET /api/v1/subscriptions
  Response 200: { subscriptions: [...], total, page }
  Auth: authenticated
  RBAC: admin, support

GET /api/v1/subscriptions/:id
  Response 200: { subscription }
  Auth: authenticated
  RBAC: admin, support
  ABAC: support agents see only assigned customers

PATCH /api/v1/subscriptions/:id
  Body: { plan_id? }  -- upgrade or downgrade
  Response 200: { subscription }
  Auth: authenticated
  RBAC: admin only
```

### Payment / Purchase Endpoints

```
POST /api/v1/payments/product
  Body: { product_id, coupon_code?, payment_method_id }
  Response 201: { payment_intent: { id, client_secret, amount } }
  Auth: authenticated
  RBAC: member
  Note: client_secret is returned for the frontend to confirm the payment
  Note: access is NOT granted here — wait for webhook

GET /api/v1/payments
  Response 200: { payments: [...], total, page }
  Auth: authenticated
  RBAC: admin
  ABAC: —

GET /api/v1/payments/me
  Response 200: { payments: [...] }
  Auth: authenticated
  RBAC: any authenticated user
  ABAC: only the requesting user's payments
```

### Coupon Endpoints

```
POST /api/v1/coupons/validate
  Body: { code, product_id?, plan_id? }
  Response 200: { valid: true, discount_type, discount_value, final_amount_cents }
  Response 200: { valid: false, reason: "EXPIRED" | "MAX_USES_REACHED" | "NOT_FOUND" | "ALREADY_USED" }
  Auth: authenticated
  RBAC: member

POST /api/v1/coupons
  Body: { code, discount_type, discount_value, max_uses?, expires_at?, applies_to }
  Response 201: { coupon }
  Auth: authenticated
  RBAC: admin

GET /api/v1/coupons
  Response 200: { coupons: [...] }
  Auth: authenticated
  RBAC: admin

DELETE /api/v1/coupons/:id
  Response 204 (deactivates, doesn't delete)
  Auth: authenticated
  RBAC: admin
```

### Invoice Endpoints

```
GET /api/v1/invoices/me
  Response 200: { invoices: [...] }
  Auth: authenticated
  RBAC: any authenticated user
  ABAC: only the requesting user's invoices

GET /api/v1/invoices/:id
  Response 200: { invoice }
  Auth: authenticated
  RBAC: admin, support, or owner
  ABAC: member can only view their own invoices

GET /api/v1/invoices
  Response 200: { invoices: [...], total, page }
  Auth: authenticated
  RBAC: admin, support
```

---

### Webhook Endpoint

```
POST /api/v1/webhooks/stripe
  Body: raw Stripe webhook payload
  Headers: stripe-signature (required for verification)
  Response 200: { received: true }
  Response 400: invalid signature
  Auth: none (verified by Stripe signature, not JWT)
  Note: this endpoint NEVER returns an error status for valid signatures,
        even if processing fails — Stripe will retry on non-200 responses
```

GET /api/v1/admin/reports/revenue

GET /api/v1/admin/audit-logs

  Response 200: { logs: [...], total, page }

  RBAC: admin

## The Auth Strategy Table (Quick Reference)

| Endpoint group | RBAC | ABAC |
|---------------|------|------|
| `POST /auth/*` | Public | — |
| `GET /users/me` | Any authenticated | Own profile only |
| `PATCH /users/me` | member, admin | Own profile only |
| `GET /users` | admin, support | support sees limited fields |
| `PATCH /users/:id` | admin | Cannot modify org owner |
| `GET /products` | Public | — |
| `POST /products` | admin | — |
| `POST /products/:id/prices` | admin | — |
| `POST /subscriptions` | member | One active sub per user |
| `GET /subscriptions/me` | Any authenticated | Own sub only |
| `PATCH /subscriptions/me/cancel` | member | Own sub only |
| `GET /subscriptions` | admin, support | support sees assigned only |
| `POST /payments/product` | member | — |
| `POST /coupons/validate` | member | — |
| `POST /coupons` | admin | — |
| `POST /webhooks/stripe` | No JWT (Stripe sig) | — |
| `GET /admin/*` | admin | — |
