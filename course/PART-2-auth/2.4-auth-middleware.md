# Lesson 2.4 — Auth Middleware

## What Is Middleware?

In web frameworks, **middleware** is a function that runs between the incoming request and your handler (the function that actually processes the request and returns a response).

Think of it as a security checkpoint. Every request to a protected endpoint passes through the middleware first. If it passes, the request continues. If it fails, the middleware rejects it immediately and the handler never runs.

```
Request → Middleware → Handler → Response
            ↓ (if rejected)
          401/403 Response (handler never runs)
```

You can chain multiple middleware functions. For our system:

```
Request → authenticate → requireRole('admin') → Handler
```

Each middleware can pass control to the next one (`next()`) or reject the request (`return res.status(401)...`).

## The Authentication Middleware

This runs on every protected endpoint. Its job: verify the JWT and attach the user to the request.

```javascript
// middleware/authenticate.js
import { verifyAccessToken } from '../utils/tokens.js'

export async function authenticate(req, res, next) {
  // 1. Extract the token from the Authorization header
  const authHeader = req.headers.authorization
  
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({
      error: {
        code: 'MISSING_TOKEN',
        message: 'Authentication required. Please log in.',
      }
    })
  }
  
  const token = authHeader.slice(7) // Remove "Bearer " prefix
  
  // 2. Verify the token
  let payload
  try {
    payload = verifyAccessToken(token)
  } catch (err) {
    // jwt.verify throws if invalid or expired
    const code = err.name === 'TokenExpiredError' ? 'TOKEN_EXPIRED' : 'INVALID_TOKEN'
    return res.status(401).json({
      error: {
        code,
        message: code === 'TOKEN_EXPIRED'
          ? 'Your session has expired. Please log in again.'
          : 'Invalid authentication token.',
      }
    })
  }
  
  // 3. Check the user still exists and isn't deleted
  // We do this because:
  // - A deleted user's token is still cryptographically valid until expiry
  // - We need to catch this case
  const user = await db.users.findById(payload.user_id)
  if (!user || user.deleted_at) {
    return res.status(401).json({
      error: { code: 'USER_NOT_FOUND', message: 'Account not found or has been deactivated.' }
    })
  }
  
  // 4. Attach the user to the request — all subsequent middleware and handlers can use it
  req.user = {
    id: user.id,
    email: user.email,
    role: payload.role,  // from token (fast, no extra DB query)
    organization_id: user.organization_id,
  }
  
  // 5. Pass control to the next middleware or handler
  next()
}
```

Usage on a route:

```javascript
// routes/products.js
import { authenticate } from '../middleware/authenticate.js'
import { requireRole } from '../middleware/requireRole.js'

router.get('/products', getProducts)                                    // public
router.post('/products', authenticate, requireRole('admin'), createProduct) // protected
```

The public `GET /products` has no middleware. The `POST /products` requires authentication AND the admin role.

## The Optional Auth Middleware

Some endpoints need to behave differently for logged-in vs anonymous users (e.g., show "your subscription" info if logged in, otherwise show nothing). For these, use an optional auth middleware:

```javascript
// middleware/optionalAuth.js
export async function optionalAuth(req, res, next) {
  const authHeader = req.headers.authorization
  
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    req.user = null  // Not authenticated, but that's okay
    return next()
  }
  
  try {
    const token = authHeader.slice(7)
    const payload = verifyAccessToken(token)
    const user = await db.users.findById(payload.user_id)
    
    req.user = user && !user.deleted_at
      ? { id: user.id, email: user.email, role: payload.role, organization_id: user.organization_id }
      : null
  } catch {
    req.user = null  // Invalid token = treat as anonymous
  }
  
  next()
}
```

## The Refresh Token Endpoint

When the access token expires, the client sends the refresh token to get a new one:

```javascript
// routes/auth.js
export async function refresh(req, res) {
  const refreshToken = req.cookies.refresh_token
  
  if (!refreshToken) {
    return res.status(401).json({
      error: { code: 'MISSING_REFRESH_TOKEN', message: 'No refresh token provided.' }
    })
  }
  
  // Verify the refresh token
  let payload
  try {
    payload = verifyRefreshToken(refreshToken)
  } catch {
    return res.status(401).json({
      error: { code: 'INVALID_REFRESH_TOKEN', message: 'Invalid or expired refresh token.' }
    })
  }
  
  // Check the user
  const user = await db.users.findById(payload.user_id)
  if (!user || user.deleted_at) {
    return res.status(401).json({
      error: { code: 'USER_NOT_FOUND', message: 'Account not found.' }
    })
  }
  
  // Get the current role (refresh tokens are long-lived, role may have changed)
  const role = await db.userRoles.getPrimaryRole(user.id)
  
  // Issue new tokens (rotation)
  const newAccessToken = generateAccessToken(user.id, role.name)
  const newRefreshToken = generateRefreshToken(user.id)
  
  // Replace the refresh token cookie
  res.cookie('refresh_token', newRefreshToken, {
    httpOnly: true,
    secure: config.nodeEnv === 'production',
    sameSite: 'strict',
    maxAge: 30 * 24 * 60 * 60 * 1000,
  })
  
  return res.json({
    access_token: newAccessToken,
  })
}
```

Notice: when refreshing, we re-query the role from the database. This is the one place where we hit the DB to get the role, because:
1. Refresh tokens are long-lived (30 days) — roles can change in that time
2. This endpoint is called rarely (only when access token expires, every 15 minutes)
3. The cost is acceptable compared to the accuracy benefit

## The Logout Endpoint

```javascript
export async function logout(req, res) {
  // Clear the refresh token cookie
  res.clearCookie('refresh_token', {
    httpOnly: true,
    secure: config.nodeEnv === 'production',
    sameSite: 'strict',
  })
  
  // If you have a refresh token blocklist or DB table, invalidate it here
  // await db.refreshTokens.invalidate(req.cookies.refresh_token)
  
  return res.status(204).send()
}
```

Note: you can't "revoke" a JWT access token that's already been issued (unless you maintain a blocklist). Clearing the cookie and removing the access token from client memory is sufficient for most applications, because the access token expires in 15 minutes anyway.

## The 401 vs 403 Review

In your authenticate middleware:
- No token or invalid token → **401** (you're not authenticated)
- Expired token → **401** (your auth expired, please re-authenticate)

In your authorization middleware (next lesson):
- Valid token, wrong role → **403** (you're authenticated, but not allowed)
- Valid token, wrong owner → **403** (you're authenticated, but not allowed to touch this)

The client uses these status codes to decide behavior:
- On 401: redirect to login
- On 403: show "Access Denied", stay on page
