# Lesson 3.4 — Seeding Roles, Permissions, and Test Data

## What Is Seeding?

**Seeding** is pre-loading your database with known-good data that the application needs to function.

There are two types of seeds:

**Required seeds** — data that must exist for the app to work at all. Roles and permissions are required seeds. If the `admin` role doesn't exist, no one can ever be an admin. These run in every environment: development, staging, and production.

**Test seeds** — data used only for testing and development. Fake users with known passwords, active subscriptions in specific states, specific coupon codes. These run only in development and test environments. Never in production.

---

## Why Roles and Permissions Are Seeded, Not Created by Users

A common beginner mistake: making an admin panel that lets users create roles and assign permissions.

This creates a circular problem: who creates the first admin role? Who assigns the first admin permission?

More importantly: **roles and permissions are code, not data.** When a developer adds a new permission (`analytics:read`, for example), they write code that checks for it in the middleware. The permission must exist in the database at the moment that code runs. The correct place to add it is in a migration or seed — not in a runtime admin panel.

Users can be assigned to roles. The roles themselves are defined by engineers.

## Seed File Structure

```
src/
└── db/
    └── seeds/
        ├── 01-roles.js          ← Always runs
        ├── 02-permissions.js    ← Always runs
        ├── 03-role-permissions.js ← Always runs
        └── test/
            ├── 01-users.js      ← Development and test only
            ├── 02-subscriptions.js
            └── 03-coupons.js
```

Seeds are numbered so they run in order. Dependencies matter: permissions must exist before you can assign them to roles.

## Required Seeds

### `01-roles.js`

```javascript
export async function seed(db) {
  // Use ON CONFLICT DO NOTHING — running seeds twice should be safe
  await db.query(`
    INSERT INTO roles (id, name, description) VALUES
      (uuid_generate_v4(), 'guest',   'Unauthenticated visitor — no permissions'),
      (uuid_generate_v4(), 'member',  'Registered user with standard access'),
      (uuid_generate_v4(), 'support', 'Customer support agent'),
      (uuid_generate_v4(), 'admin',   'Platform administrator — full access')
    ON CONFLICT (name) DO NOTHING
  `)
  
  console.log('✓ Roles seeded')
}
```

### `02-permissions.js`

```javascript
const PERMISSIONS = [
  // Products
  ['products:read',          'View products and product details'],
  ['products:write',         'Create and update products'],
  ['products:delete',        'Deactivate products'],
  // Prices
  ['prices:read',            'View price history'],
  ['prices:write',           'Create new price records'],
  // Plans
  ['plans:read',             'View subscription plans'],
  ['plans:write',            'Create and update plans'],
  // Subscriptions
  ['subscriptions:read_own', 'Read own subscription'],
  ['subscriptions:read_all', 'Read all subscriptions'],
  ['subscriptions:manage',   'Change subscription plans'],
  ['subscriptions:cancel',   'Cancel a subscription'],
  // Users
  ['users:read_own',         'Read own user data'],
  ['users:read_all',         'Read all user data'],
  ['users:manage',           'Update user accounts and roles'],
  ['users:delete',           'Deactivate user accounts'],
  // Payments
  ['payments:read_own',      'View own payment history'],
  ['payments:read_all',      'View all payment history'],
  // Coupons
  ['coupons:read',           'View coupon definitions'],
  ['coupons:write',          'Create and manage coupons'],
  ['coupons:use',            'Apply coupons at checkout'],
  // Reports
  ['reports:read',           'View admin reports and analytics'],
  // Audit logs
  ['audit_logs:read',        'View audit logs'],
  // Content (subscription-gated features)
  ['content:read',           'Access subscription-gated content'],
]

export async function seed(db) {
  for (const [name, description] of PERMISSIONS) {
    await db.query(`
      INSERT INTO permissions (id, name, description)
      VALUES (uuid_generate_v4(), $1, $2)
      ON CONFLICT (name) DO NOTHING
    `, [name, description])
  }
  
  console.log(`✓ ${PERMISSIONS.length} permissions seeded`)
}
```

### `03-role-permissions.js`

```javascript
const ROLE_PERMISSIONS = {
  member: [
    'products:read',
    'plans:read',
    'subscriptions:read_own',
    'subscriptions:cancel',
    'users:read_own',
    'payments:read_own',
    'coupons:use',
    'content:read',
  ],
  support: [
    'products:read',
    'plans:read',
    'subscriptions:read_all',
    'users:read_all',
    'payments:read_all',
    'coupons:read',
  ],
  admin: [
    // Admins get everything
    'products:read', 'products:write', 'products:delete',
    'prices:read', 'prices:write',
    'plans:read', 'plans:write',
    'subscriptions:read_own', 'subscriptions:read_all', 'subscriptions:manage', 'subscriptions:cancel',
    'users:read_own', 'users:read_all', 'users:manage', 'users:delete',
    'payments:read_own', 'payments:read_all',
    'coupons:read', 'coupons:write', 'coupons:use',
    'reports:read',
    'audit_logs:read',
    'content:read',
  ],
}

export async function seed(db) {
  for (const [roleName, permissions] of Object.entries(ROLE_PERMISSIONS)) {
    for (const permissionName of permissions) {
      await db.query(`
        INSERT INTO role_permissions (role_id, permission_id)
        SELECT r.id, p.id
        FROM roles r, permissions p
        WHERE r.name = $1 AND p.name = $2
        ON CONFLICT DO NOTHING
      `, [roleName, permissionName])
    }
  }
  
  console.log('✓ Role permissions seeded')
}
```

## Test Seeds

These create known, predictable data for development and testing.

### `test/01-users.js`

```javascript
import bcrypt from 'bcrypt'

// These are known credentials for testing
// NEVER use these in production
const TEST_USERS = [
  {
    email: 'admin@test.com',
    password: 'TestPassword123!',
    display_name: 'Test Admin',
    role: 'admin',
  },
  {
    email: 'member@test.com',
    password: 'TestPassword123!',
    display_name: 'Test Member (Active)',
    role: 'member',
  },
  {
    email: 'member-trial@test.com',
    password: 'TestPassword123!',
    display_name: 'Test Member (Trial)',
    role: 'member',
  },
  {
    email: 'member-lapsed@test.com',
    password: 'TestPassword123!',
    display_name: 'Test Member (Lapsed)',
    role: 'member',
  },
  {
    email: 'support@test.com',
    password: 'TestPassword123!',
    display_name: 'Test Support Agent',
    role: 'support',
  },
]

export async function seed(db) {
  if (process.env.NODE_ENV === 'production') {
    throw new Error('CANNOT run test seeds in production')
  }
  
  for (const userData of TEST_USERS) {
    const passwordHash = await bcrypt.hash(userData.password, 8)  // Low rounds for test speed
    
    const result = await db.query(`
      INSERT INTO users (id, email, password_hash, display_name)
      VALUES (uuid_generate_v4(), $1, $2, $3)
      ON CONFLICT (email) DO UPDATE
        SET password_hash = $2, display_name = $3
      RETURNING id
    `, [userData.email, passwordHash, userData.display_name])
    
    const userId = result.rows[0].id
    
    // Assign role
    await db.query(`
      INSERT INTO user_roles (user_id, role_id)
      SELECT $1, r.id FROM roles r WHERE r.name = $2
      ON CONFLICT DO NOTHING
    `, [userId, userData.role])
  }
  
  console.log(`✓ ${TEST_USERS.length} test users seeded`)
  console.log('  Credentials:')
  TEST_USERS.forEach(u => console.log(`  ${u.email} / ${u.password} [${u.role}]`))
}
```

### `test/02-subscriptions.js`

```javascript
export async function seed(db) {
  if (process.env.NODE_ENV === 'production') {
    throw new Error('CANNOT run test seeds in production')
  }
  
  // Get test users and the monthly plan
  const users = await db.query(`
    SELECT u.id, u.email FROM users u
    WHERE u.email IN ('member@test.com', 'member-trial@test.com', 'member-lapsed@test.com')
  `)
  
  const plan = await db.query(`
    SELECT p.id FROM plans p WHERE p.name = 'Monthly' LIMIT 1
  `)
  
  if (!plan.rows.length) {
    console.warn('⚠ No plans found — run product/plan seeds first')
    return
  }
  
  const planId = plan.rows[0].id
  
  const userMap = {}
  users.rows.forEach(u => { userMap[u.email] = u.id })
  
  // Active subscriber
  if (userMap['member@test.com']) {
    await db.query(`
      INSERT INTO subscriptions (
        id, user_id, plan_id, stripe_subscription_id, status,
        current_period_start, current_period_end
      ) VALUES (
        uuid_generate_v4(), $1, $2, 'sub_test_active_001', 'active',
        NOW() - INTERVAL '15 days', NOW() + INTERVAL '15 days'
      )
      ON CONFLICT (stripe_subscription_id) DO NOTHING
    `, [userMap['member@test.com'], planId])
  }
  
  // Trial subscriber
  if (userMap['member-trial@test.com']) {
    await db.query(`
      INSERT INTO subscriptions (
        id, user_id, plan_id, stripe_subscription_id, status,
        trial_ends_at, current_period_start, current_period_end
      ) VALUES (
        uuid_generate_v4(), $1, $2, 'sub_test_trial_001', 'trialing',
        NOW() + INTERVAL '7 days',
        NOW(), NOW() + INTERVAL '30 days'
      )
      ON CONFLICT (stripe_subscription_id) DO NOTHING
    `, [userMap['member-trial@test.com'], planId])
  }
  
  // Lapsed subscriber (past_due)
  if (userMap['member-lapsed@test.com']) {
    await db.query(`
      INSERT INTO subscriptions (
        id, user_id, plan_id, stripe_subscription_id, status,
        current_period_start, current_period_end
      ) VALUES (
        uuid_generate_v4(), $1, $2, 'sub_test_lapsed_001', 'past_due',
        NOW() - INTERVAL '35 days', NOW() - INTERVAL '5 days'
      )
      ON CONFLICT (stripe_subscription_id) DO NOTHING
    `, [userMap['member-lapsed@test.com'], planId])
  }
  
  console.log('✓ Test subscriptions seeded')
}
```

## The Seed Runner

```javascript
// db/seed.js
import { seed as seedRoles } from './seeds/01-roles.js'
import { seed as seedPermissions } from './seeds/02-permissions.js'
import { seed as seedRolePermissions } from './seeds/03-role-permissions.js'
import { seed as seedTestUsers } from './seeds/test/01-users.js'
import { seed as seedTestSubscriptions } from './seeds/test/02-subscriptions.js'
import db from './index.js'

async function run() {
  const isTest = process.env.NODE_ENV !== 'production'
  
  console.log('Running required seeds...')
  await seedRoles(db)
  await seedPermissions(db)
  await seedRolePermissions(db)
  
  if (isTest) {
    console.log('\nRunning test seeds...')
    await seedTestUsers(db)
    await seedTestSubscriptions(db)
  }
  
  console.log('\n✓ All seeds complete')
  process.exit(0)
}

run().catch(err => {
  console.error('Seed failed:', err)
  process.exit(1)
})
```

Add to `package.json`:
```json
{
  "scripts": {
    "db:seed": "node src/db/seed.js",
    "db:migrate": "node src/db/migrate.js",
    "db:reset": "npm run db:migrate && npm run db:seed"
  }
}
```

## The Idempotency Rule for Seeds

Every seed must be **idempotent**: running it twice must produce the same result as running it once. This is why every INSERT uses `ON CONFLICT DO NOTHING` or `ON CONFLICT DO UPDATE`.

If a seed isn't idempotent, running it after an error (and re-running it to fix things) causes duplicate data. Duplicate data in roles and permissions is chaos.

## Summary

| Seed type | When it runs | Purpose |
|-----------|-------------|---------|
| Required seeds | Every environment | Roles, permissions, role-permission mappings |
| Test seeds | Dev and test only | Known users, subscriptions, coupons for testing |
| Production seed run | Only required seeds | `NODE_ENV=production node db/seed.js` |
