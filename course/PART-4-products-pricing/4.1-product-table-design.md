# Lesson 4.1 — The Product Table Design

## Products and Prices Are Different Things

This is one of the most important design decisions in this entire course, and most beginners get it wrong the first time.

The instinct is: "A product has a price. I'll add a `price` column to the products table."

```sql
-- WRONG approach
CREATE TABLE products (
  id    UUID PRIMARY KEY,
  name  TEXT NOT NULL,
  price INTEGER NOT NULL  -- This breaks everything later
)
```

This works until your business does any of the following:
- Raises the price for new customers but keeps existing ones on the old price
- Runs a temporary sale and returns to the original price
- Offers a different currency to international customers
- Wants to show customers "you're saving $10/month vs the current price"

All of these require price history. If you store price as a column on the product, you have no history — just the current value. The moment you update it, the past is gone.

**The correct model: Products and Prices are separate entities.**

Stripe figured this out early, which is why their API has separate `Product` and `Price` objects. We mirror this design because we mirror Stripe's data (we'll store Stripe's IDs alongside ours).

## The Products Table

```javascript
// handlers/products.js

export async function createProduct(req, res) {
  const { name, description, amount_cents, currency = 'usd' } = req.body
  
  if (!name || !amount_cents) {
    return res.status(400).json({
      error: { code: 'MISSING_FIELDS', message: 'name and amount_cents are required.' }
    })
  }
  
  if (amount_cents < 0) {
    return res.status(400).json({
      error: { code: 'INVALID_PRICE', message: 'Price cannot be negative.' }
    })
  }
  
  // Create product in Stripe first (covered in Part 5)
  // const stripeProduct = await stripe.products.create({ name })
  // const stripePrice = await stripe.prices.create({ ... })
  
  // Create in our DB
  const product = await db.query(`
    INSERT INTO products (id, name, description, stripe_product_id)
    VALUES (uuid_generate_v4(), $1, $2, $3)
    RETURNING *
  `, [name, description, null /* stripeProduct.id */])
  
  // Always create the first price alongside the product
  const price = await db.query(`
    INSERT INTO prices (id, product_id, amount_cents, currency, applies_to, is_current)
    VALUES (uuid_generate_v4(), $1, $2, $3, 'future_members', true)
    RETURNING *
  `, [product.rows[0].id, amount_cents, currency])
  
  // Audit log
  await db.query(`
    INSERT INTO audit_logs (id, actor_id, actor_type, action, resource_type, resource_id, metadata)
    VALUES (uuid_generate_v4(), $1, 'user', 'product.created', 'product', $2, $3)
  `, [req.user.id, product.rows[0].id, JSON.stringify({ name, amount_cents })])
  
  return res.status(201).json({
    product: product.rows[0],
    price: price.rows[0],
  })
}


export async function listProducts(req, res) {
  // Public endpoint — returns only active products with their current price
  const products = await db.query(`
    SELECT 
      p.id,
      p.name,
      p.description,
      p.is_active,
      pr.id as price_id,
      pr.amount_cents,
      pr.currency,
      pr.stripe_price_id
    FROM products p
    LEFT JOIN prices pr ON pr.product_id = p.id AND pr.is_current = true
    WHERE p.deleted_at IS NULL
      AND p.is_active = true
    ORDER BY p.created_at ASC
  `)
  
  return res.json({ products: products.rows })
}
```

## Adding a New Price (The Admin Workflow)

When an admin changes a price, the workflow is:

1. Mark the existing current price as `is_current = false`
2. Insert a new price record with `is_current = true` and the `applies_to` rule
3. Create the corresponding price in Stripe
4. Log the change to audit_logs

```javascript
export async function addPrice(req, res) {
  const { id: productId } = req.params
  const { amount_cents, currency = 'usd', applies_to, applies_from_date } = req.body
  
  // Validate applies_to
  const validAppliesTo = ['future_members', 'all_members', 'from_date']
  if (!validAppliesTo.includes(applies_to)) {
    return res.status(400).json({
      error: {
        code: 'INVALID_APPLIES_TO',
        message: `applies_to must be one of: ${validAppliesTo.join(', ')}`
      }
    })
  }
  
  if (applies_to === 'from_date' && !applies_from_date) {
    return res.status(400).json({
      error: { code: 'MISSING_DATE', message: 'applies_from_date is required when applies_to is from_date.' }
    })
  }
  
  // Get the product
  const product = await db.query(`
    SELECT * FROM products WHERE id = $1 AND deleted_at IS NULL
  `, [productId])
  
  if (!product.rows.length) {
    return res.status(404).json({ error: { code: 'NOT_FOUND', message: 'Product not found.' } })
  }
  
  // Get the old current price (for audit log)
  const oldPrice = await db.query(`
    SELECT * FROM prices WHERE product_id = $1 AND is_current = true
  `, [productId])
  
  // Transaction: mark old price inactive, create new price
  await db.transaction(async (client) => {
    // Mark previous price as not current
    await client.query(`
      UPDATE prices SET is_current = false WHERE product_id = $1 AND is_current = true
    `, [productId])
    
    // Create the new price
    const newPrice = await client.query(`
      INSERT INTO prices (id, product_id, amount_cents, currency, applies_to, applies_from_date, is_current)
      VALUES (uuid_generate_v4(), $1, $2, $3, $4, $5, true)
      RETURNING *
    `, [productId, amount_cents, currency, applies_to, applies_from_date ?? null])
    
    // Audit log
    await client.query(`
      INSERT INTO audit_logs (id, actor_id, actor_type, action, resource_type, resource_id, metadata)
      VALUES (uuid_generate_v4(), $1, 'user', 'price.updated', 'product', $2, $3)
    `, [
      req.user.id,
      productId,
      JSON.stringify({
        old_amount_cents: oldPrice.rows[0]?.amount_cents,
        new_amount_cents: amount_cents,
        applies_to,
        applies_from_date,
      })
    ])
    
    return newPrice.rows[0]
  })
  
  return res.status(201).json({ price: newPrice })
}
```

## The `applies_to` Logic (Grandfathering at the Query Level)

Given the `applies_to` field, how do you query "what price does user X pay for product Y right now?"

```sql
-- "What is the correct price for user X on product Y?"
-- This handles all three applies_to cases

SELECT pr.*
FROM prices pr
WHERE pr.product_id = $1  -- the product
  AND (
    -- Case 1: price applies to all members
    pr.applies_to = 'all_members'
    
    -- Case 2: price applies to future members and user joined after it was set
    OR (pr.applies_to = 'future_members' AND pr.created_at <= $2)  -- $2 = user.created_at
    
    -- Case 3: price applies from a specific date and user joined after that date
    OR (pr.applies_to = 'from_date' AND pr.applies_from_date <= $2)
  )
ORDER BY pr.created_at DESC
LIMIT 1
```

But for subscriptions, the simpler approach is to store `locked_price_id` at subscription creation time (as designed in the schema). Then querying is trivial:

```sql
-- For a subscription: use the locked price
SELECT pr.*
FROM subscriptions s
JOIN prices pr ON pr.id = s.locked_price_id
WHERE s.id = $1
```

The `applies_to` query is used for one-time product purchases (where there's no "locked" price) and for the checkout page to show the correct price to the user before they buy.

---

## Key Principles

1. **Never UPDATE a price row.** Only INSERT new ones.
2. **Always use transactions** when changing prices (mark old inactive + insert new in one atomic operation).
3. **Always audit log** price changes — admins need to see when prices changed and who changed them.
4. **Store `locked_price_id` on subscriptions** at creation time — don't re-compute the grandfathered price on every billing cycle.
5. **Mirror Stripe's structure** — one Stripe Product per product/plan, one Stripe Price per price record.
