# Lesson 4.3 — Grandfathering Logic

## What Grandfathering Is

Grandfathering is a business promise: "We're raising prices, but you joined when the price was lower, and we'll keep charging you the old price forever."

This happens constantly in subscription businesses. A company grows, their costs increase, they need to charge more — but they don't want to lose existing happy customers by forcing the new price on them.

The technical challenge: you need to remember, for each subscriber, what price they agreed to. And when Stripe bills them, you need to make sure Stripe is using that price, not the new one.

---

## The Two Implementation Approaches

### Approach A: `locked_price_id` on the Subscription (Recommended)

When a user subscribes, you record exactly which price they're subscribing to:

```sql
subscriptions.locked_price_id = 'abc-123'  -- the specific price record they agreed to
```

This is the approach we use. Here's why it's better:

- Simple to query: "what price does user X pay?" → `JOIN prices ON subscriptions.locked_price_id = prices.id`
- The source of truth is explicit
- No complex date math needed at billing time
- Stripe also has this price locked (their subscription is tied to a specific Stripe Price ID)

### Approach B: `user_prices` override table

A separate table that stores per-user price overrides:
```sql
user_prices (user_id, product_id, price_id, locked_until)
```

This is useful when you want to:
- Give specific users custom prices that aren't part of the normal price history
- Set temporary pricing exceptions
- Handle complex enterprise deals with custom rates

For our course project, Approach A is sufficient. Approach B is for more complex scenarios.

## The Subscription Creation Flow With Locking

```javascript
// handlers/subscriptions.js

export async function createSubscription(req, res) {
  const { plan_id, payment_method_id, coupon_code } = req.body
  const user = req.user
  
  // 1. Check for existing active subscription
  const existing = await db.query(`
    SELECT id FROM subscriptions
    WHERE user_id = $1
      AND status IN ('active', 'trialing', 'past_due')
      AND deleted_at IS NULL
    LIMIT 1
  `, [user.id])
  
  if (existing.rows.length) {
    return res.status(409).json({
      error: { code: 'SUBSCRIPTION_EXISTS', message: 'You already have an active subscription.' }
    })
  }
  
  // 2. Get the plan and its CURRENT price
  const plan = await db.query(`
    SELECT p.*, pr.id as price_id, pr.amount_cents, pr.stripe_price_id
    FROM plans p
    JOIN prices pr ON pr.plan_id = p.id AND pr.is_current = true
    WHERE p.id = $1 AND p.deleted_at IS NULL AND p.is_active = true
  `, [plan_id])
  
  if (!plan.rows.length) {
    return res.status(404).json({ error: { code: 'PLAN_NOT_FOUND', message: 'Plan not found.' } })
  }
  
  const { stripe_price_id, price_id, amount_cents } = plan.rows[0]
  
  // 3. Validate and apply coupon (if provided)
  let couponDiscount = null
  if (coupon_code) {
    couponDiscount = await validateAndReserveCoupon(coupon_code, user.id, 'plan', plan_id)
    if (!couponDiscount.valid) {
      return res.status(400).json({
        error: { code: couponDiscount.reason, message: couponDiscount.message }
      })
    }
  }
  
  // 4. Attach payment method to Stripe customer
  await stripe.paymentMethods.attach(payment_method_id, {
    customer: user_stripe_customer_id,
  })
  await stripe.customers.update(user_stripe_customer_id, {
    invoice_settings: { default_payment_method: payment_method_id },
  })
  
  // 5. Create the Stripe subscription
  const stripeSubscription = await stripe.subscriptions.create({
    customer: user_stripe_customer_id,
    items: [{ price: stripe_price_id }],
    trial_period_days: config.features.trialsEnabled ? config.features.trialDays : undefined,
    coupon: couponDiscount?.stripe_coupon_id,
    expand: ['latest_invoice.payment_intent'],
  })
  
  // 6. Store locally with the LOCKED price
  const subscription = await db.query(`
    INSERT INTO subscriptions (
      id, user_id, plan_id, locked_price_id, stripe_subscription_id,
      status, trial_ends_at, current_period_start, current_period_end
    )
    VALUES (uuid_generate_v4(), $1, $2, $3, $4, $5, $6, $7, $8)
    RETURNING *
  `, [
    user.id,
    plan_id,
    price_id,                                                    // ← LOCKED HERE
    stripeSubscription.id,
    stripeSubscription.status,
    stripeSubscription.trial_end
      ? new Date(stripeSubscription.trial_end * 1000) : null,
    new Date(stripeSubscription.current_period_start * 1000),
    new Date(stripeSubscription.current_period_end * 1000),
  ])
  
  // 7. Record coupon redemption
  if (couponDiscount) {
    await db.query(`
      INSERT INTO coupon_redemptions (id, coupon_id, user_id, used_at)
      VALUES (uuid_generate_v4(), $1, $2, NOW())
    `, [couponDiscount.coupon_id, user.id])
    
    // Increment coupon usage count
    await db.query(`
      UPDATE coupons SET current_uses = current_uses + 1 WHERE id = $1
    `, [couponDiscount.coupon_id])
  }
  
  return res.status(201).json({ subscription: subscription.rows[0] })
}
```

## What Happens When a Price Changes

Scenario: The monthly plan was $19.99. You raise it to $24.99 for future members.

```
Before the change:
  prices table:
    id: price_A, plan_id: monthly, amount_cents: 1999, is_current: true

Admin action: "Change price to $24.99 for future_members"

After the change:
  prices table:
    id: price_A, plan_id: monthly, amount_cents: 1999, is_current: FALSE
    id: price_B, plan_id: monthly, amount_cents: 2499, is_current: TRUE
```

**Users who subscribed before the change:**
```
subscriptions (Alice, subscribed at price_A):
  locked_price_id: price_A   ← still points to the old price
  stripe_subscription: sub_xxx with Stripe Price price_A.stripe_price_id
```

Alice's Stripe subscription is still on the old Stripe Price. Stripe keeps charging her $19.99. Nothing changes for Alice.

**Users who subscribe after the change:**
```
subscriptions (Bob, subscribing now):
  locked_price_id: price_B   ← points to the new price
  stripe_subscription: sub_yyy with Stripe Price price_B.stripe_price_id
```

Bob gets charged $24.99.

## The `applies_to = 'all_members'` Case

If the admin chooses "apply to all members," you need to update existing subscribers too.

This is more complex because you need to:
1. Update the `locked_price_id` on all active subscriptions
2. Update each subscriber's Stripe subscription to use the new Stripe Price
3. Stripe will handle proration

```javascript
async function applyPriceToAllMembers(newPriceId, stripePriceId, planId) {
  // Get all active subscriptions for this plan
  const subscriptions = await db.query(`
    SELECT s.id, s.stripe_subscription_id
    FROM subscriptions s
    WHERE s.plan_id = $1
      AND s.status IN ('active', 'trialing', 'past_due')
      AND s.deleted_at IS NULL
  `, [planId])
  
  for (const sub of subscriptions.rows) {
    // Update Stripe subscription to new price
    const stripeSub = await stripe.subscriptions.retrieve(sub.stripe_subscription_id)
    await stripe.subscriptions.update(sub.stripe_subscription_id, {
      items: [{
        id: stripeSub.items.data[0].id,
        price: stripePriceId,
      }],
      proration_behavior: 'none',  // No proration — price change takes effect at next billing
    })
    
    // Update local locked_price_id
    await db.query(`
      UPDATE subscriptions SET locked_price_id = $1 WHERE id = $2
    `, [newPriceId, sub.id])
  }
  
  // Audit log
  await db.auditLogs.create({
    actor_type: 'system',
    action: 'price.applied_to_all_members',
    resource_type: 'plan',
    resource_id: planId,
    metadata: { new_price_id: newPriceId, affected_count: subscriptions.rows.length }
  })
}
```

## Querying "What Does This User Pay?"

For display purposes (checkout, billing page, account settings):

```javascript
export async function getUserSubscriptionPrice(userId) {
  const result = await db.query(`
    SELECT 
      s.id as subscription_id,
      s.status,
      p.name as plan_name,
      p.interval,
      p.interval_count,
      pr.amount_cents,
      pr.currency,
      -- Show the "current market price" for comparison
      current_pr.amount_cents as current_market_price_cents,
      -- Are they grandfathered? (paying less than current price)
      (pr.amount_cents < current_pr.amount_cents) as is_grandfathered
    FROM subscriptions s
    JOIN plans p ON p.id = s.plan_id
    JOIN prices pr ON pr.id = s.locked_price_id           -- their actual price
    LEFT JOIN prices current_pr ON current_pr.plan_id = s.plan_id AND current_pr.is_current = true
    WHERE s.user_id = $1
      AND s.status IN ('active', 'trialing', 'past_due')
      AND s.deleted_at IS NULL
    LIMIT 1
  `, [userId])
  
  return result.rows[0] ?? null
}
```

This lets you show the user: "You're on the Monthly plan at $19.99/month (current price: $24.99/month — you're grandfathered in)."

## The Principal Engineer Checklist for Grandfathering

Before implementing grandfathering in any system, answer:

1. **Where is the "locked price" stored?** On the subscription record. ✓
2. **Is the Stripe subscription also locked to the old price?** Yes — the Stripe subscription item points to the old Stripe Price. ✓
3. **When the price changes, do existing subscribers automatically stay on the old price?** Yes — their `locked_price_id` and Stripe subscription price are unchanged. ✓
4. **When an admin applies to all members, is it done atomically?** No — it's done in a loop. For large numbers of subscribers, this should be a background job, not a synchronous request. Note this limitation.
5. **Is price history preserved?** Yes — old price records are kept, just marked `is_current = false`. ✓
