# Lesson 5.1 — How Stripe Works (Mental Model)

## Why We Use Stripe Instead of Building Our Own

Processing payments is not just "charge a credit card." It involves:
- PCI DSS compliance (regulatory requirements for handling card data)
- 3D Secure authentication (European regulation)
- Fraud detection
- Handling 200+ card issuers worldwide
- Retry logic for failed payments
- Dispute management
- Tax compliance in 50+ countries

Building this from scratch would take years and require a dedicated team. Stripe has already done it. Your job is to integrate correctly with Stripe, not to replace it.

---

## Stripe's Object Model

Stripe is a separate system with its own database. When you create objects in Stripe, you get back IDs. You store those IDs in your database alongside your own IDs.

| Stripe Object | What It Is | Where You Store It |
|--------------|-----------|-------------------|
| `Customer` | Stripe's record of a person | `users.stripe_customer_id` |
| `PaymentMethod` | A saved credit card | Referenced by Customer (managed by Stripe) |
| `Product` | An item for sale | `products.stripe_product_id`, `plans.stripe_product_id` |
| `Price` | How much a Product costs | `prices.stripe_price_id` |
| `PaymentIntent` | An intent to charge (one-time) | `payments.stripe_payment_intent_id` |
| `Subscription` | A recurring billing relationship | `subscriptions.stripe_subscription_id` |
| `Invoice` | A billing record | `invoices.stripe_invoice_id` |
| `Coupon` | A discount | `coupons.stripe_coupon_id` |
| `Webhook Event` | A notification Stripe sends you | `webhook_events.stripe_event_id` |

**The key principle:** Stripe's data is the source of truth for payment status. Your database mirrors Stripe's state and extends it with business logic (roles, grandfathering, org structure, etc.).

## Test Mode vs Live Mode

Stripe has two completely separate environments:

**Test mode** — No real money moves. Use test card numbers. All events can be simulated. This is what you use during development.

**Live mode** — Real money, real cards, real consequences. This is production.

Your `.env.example` has:
```
STRIPE_SECRET_KEY=sk_test_...   # Never use sk_live_ in development
STRIPE_PUBLISHABLE_KEY=pk_test_...
```

Going to production is simple: swap `sk_test_` for `sk_live_` and `pk_test_` for `pk_live_`. The rest of your code doesn't change.

## The Payment Flow (Overview)

For one-time purchases, Stripe uses a two-step flow:

```
Client                    Your Server              Stripe
  |                           |                       |
  | POST /payments/product    |                       |
  |──────────────────────────>|                       |
  |                           | Create PaymentIntent  |
  |                           |──────────────────────>|
  |                           | PaymentIntent(id, cs) |
  |                           |<──────────────────────|
  |   { client_secret }       |                       |
  |<──────────────────────────|                       |
  |                           |                       |
  | Stripe.js confirms payment|                       |
  |──────────────────────────────────────────────────>|
  |                           |                       |
  |                           |    Webhook: payment_intent.succeeded
  |                           |<──────────────────────|
  |                           | Update DB, grant access|
  |                           |──────(internal)────── |
```

Notice: your server creates the PaymentIntent. The client completes the payment using Stripe.js (Stripe's frontend library). Then Stripe notifies your server via webhook when it succeeds.

**You never see the card number.** Stripe.js sends the card directly to Stripe's servers. Your server only sees the PaymentIntent ID and the client_secret.

## The Subscription Flow (Overview)

```
Client                    Your Server              Stripe
  |                           |                       |
  | POST /subscriptions       |                       |
  |──────────────────────────>|                       |
  |                           | Attach PaymentMethod  |
  |                           |──────────────────────>|
  |                           | Create Subscription   |
  |                           |──────────────────────>|
  |                           | Subscription object   |
  |                           |<──────────────────────|
  |                           | Store locally         |
  |   { subscription }        |                       |
  |<──────────────────────────|                       |
  |                           |                       |
  |               (at billing time)                   |
  |                           |    Webhook: invoice.paid
  |                           |<──────────────────────|
  |                           | Update subscription   |
  |                           | status in DB          |
```

For subscriptions, the flow is slightly different:
1. Client provides a PaymentMethod (card) via Stripe.js
2. Your server creates the subscription in Stripe
3. Stripe immediately attempts the first charge (or starts a trial)
4. Stripe notifies your server of the result via webhook
5. Your server updates the subscription status and grants/denies access accordingly

---

## The Most Important Rule in Stripe Integration

**Never trust the client to confirm payment.**

A client can send you any request. If your "payment successful" endpoint is `POST /payments/confirm` and you grant access just because the client posts to it, any attacker can call that endpoint without paying.

Instead:
- The client completes payment via Stripe.js (talking directly to Stripe)
- Stripe sends YOUR SERVER a webhook when payment succeeds
- YOUR SERVER updates the database and grants access

The webhook is the only signal you trust. The client calling any endpoint is never a payment confirmation.

## Setting Up Stripe in Your Application

```javascript
// services/stripe.js
import Stripe from 'stripe'
import { config } from '../config.js'

export const stripe = new Stripe(config.stripe.secretKey, {
  apiVersion: '2024-04-10',  // Pin to a specific API version
})

// Create a Stripe customer for a new user
export async function createStripeCustomer(user) {
  return stripe.customers.create({
    email: user.email,
    name: user.display_name,
    metadata: {
      user_id: user.id,  // Link back to your system
    },
  })
}

// Sync a product to Stripe
export async function createStripeProduct(product) {
  return stripe.products.create({
    name: product.name,
    description: product.description,
    metadata: { product_id: product.id },
  })
}

// Sync a price to Stripe (for a product)
export async function createStripePrice(stripeProductId, amountCents, currency = 'usd') {
  return stripe.prices.create({
    product: stripeProductId,
    unit_amount: amountCents,
    currency,
  })
}

// Sync a price to Stripe (for a subscription plan)
export async function createStripePlanPrice(stripeProductId, amountCents, interval, intervalCount, currency = 'usd') {
  return stripe.prices.create({
    product: stripeProductId,
    unit_amount: amountCents,
    currency,
    recurring: {
      interval,
      interval_count: intervalCount,
    },
  })
}
```
