# Lesson 5.5 — Webhooks (The Most Important Lesson)

## What Webhooks Are

A webhook is Stripe calling your server. Instead of you asking Stripe "did that payment work?", Stripe tells you when something happens.

This is **event-driven design**: your system reacts to events, rather than polling for changes.

Stripe fires webhooks for every significant event: payment succeeded, payment failed, subscription updated, trial ending, refund issued, dispute opened. You subscribe to the events you care about.

---

## The Webhook Endpoint

This endpoint is different from all others:

1. **No JWT authentication** — Stripe doesn't have your user's JWT. It authenticates itself using a signature in the request header.
2. **Must respond quickly** — Stripe expects a `200` response within 30 seconds. If it doesn't get one, it retries.
3. **Must be idempotent** — Stripe sends the same event multiple times (at least once delivery). You must handle duplicates.
4. **Must never return 5xx** — Stripe will retry on any non-200 response. Log errors internally, but return 200 to Stripe.

```javascript
// routes/webhooks.js
import express from 'express'
import { stripe } from '../services/stripe.js'
import { config } from '../config.js'
import * as webhookHandlers from '../handlers/webhooks.js'

const router = express.Router()

// CRITICAL: This must use raw body parsing, not JSON parsing
// Stripe signature verification requires the raw byte body
router.post('/webhooks/stripe',
  express.raw({ type: 'application/json' }),  // Raw body
  async (req, res) => {
    const signature = req.headers['stripe-signature']
    
    // 1. Verify the signature
    let event
    try {
      event = stripe.webhooks.constructEvent(
        req.body,                          // raw bytes
        signature,
        config.stripe.webhookSecret
      )
    } catch (err) {
      // Invalid signature — could be a fake request
      console.error('Webhook signature verification failed:', err.message)
      return res.status(400).json({ error: 'Invalid signature' })
    }
    
    // 2. Respond immediately to Stripe — we'll process asynchronously
    res.json({ received: true })
    
    // 3. Process the event (after responding)
    await processWebhookEvent(event)
  }
)

async function processWebhookEvent(event) {
  // Check if already processed (idempotency)
  const existing = await db.query(`
    SELECT id, processed_at FROM webhook_events WHERE stripe_event_id = $1
  `, [event.id])
  
  if (existing.rows.length && existing.rows[0].processed_at) {
    // Already processed — skip
    console.log(`Webhook event ${event.id} already processed, skipping`)
    return
  }
  
  // Record the event (even if not yet processed)
  if (!existing.rows.length) {
    await db.query(`
      INSERT INTO webhook_events (id, stripe_event_id, event_type, payload)
      VALUES (uuid_generate_v4(), $1, $2, $3)
      ON CONFLICT (stripe_event_id) DO NOTHING
    `, [event.id, event.type, JSON.stringify(event)])
  }
  
  // Route to the correct handler
  try {
    await routeWebhookEvent(event)
    
    // Mark as processed
    await db.query(`
      UPDATE webhook_events SET processed_at = NOW() WHERE stripe_event_id = $1
    `, [event.id])
    
  } catch (err) {
    // Log the error but don't throw — we already sent 200 to Stripe
    console.error(`Error processing webhook ${event.id}:`, err)
    
    await db.query(`
      UPDATE webhook_events SET error = $1 WHERE stripe_event_id = $2
    `, [err.message, event.id])
  }
}

async function routeWebhookEvent(event) {
  switch (event.type) {
    // Payment events
    case 'payment_intent.succeeded':
      await webhookHandlers.onPaymentIntentSucceeded(event.data.object)
      break
    case 'payment_intent.payment_failed':
      await webhookHandlers.onPaymentIntentFailed(event.data.object)
      break
    
    // Invoice events (subscriptions)
    case 'invoice.paid':
      await webhookHandlers.onInvoicePaid(event.data.object)
      break
    case 'invoice.payment_failed':
      await webhookHandlers.onInvoicePaymentFailed(event.data.object)
      break
    
    // Subscription lifecycle
    case 'customer.subscription.created':
      await webhookHandlers.onSubscriptionCreated(event.data.object)
      break
    case 'customer.subscription.updated':
      await webhookHandlers.onSubscriptionUpdated(event.data.object)
      break
    case 'customer.subscription.deleted':
      await webhookHandlers.onSubscriptionDeleted(event.data.object)
      break
    case 'customer.subscription.trial_will_end':
      await webhookHandlers.onTrialWillEnd(event.data.object)
      break
    
    default:
      console.log(`Unhandled webhook event type: ${event.type}`)
  }
}
```

## The Webhook Handlers

```javascript
// handlers/webhooks.js

export async function onPaymentIntentSucceeded(paymentIntent) {
  // Find our payment record by Stripe's payment intent ID
  const payment = await db.query(`
    SELECT p.*, u.id as user_id
    FROM payments p
    JOIN users u ON u.id = p.user_id
    WHERE p.stripe_payment_intent_id = $1
  `, [paymentIntent.id])
  
  if (!payment.rows.length) {
    // No record found — might be from a subscription invoice, not a direct purchase
    // Check if it's linked to an invoice
    if (paymentIntent.invoice) {
      // Handle via onInvoicePaid instead
      return
    }
    console.warn(`payment_intent.succeeded: no payment found for ${paymentIntent.id}`)
    return
  }
  
  const p = payment.rows[0]
  
  // Update payment status
  await db.query(`
    UPDATE payments SET status = 'succeeded', updated_at = NOW()
    WHERE stripe_payment_intent_id = $1
  `, [paymentIntent.id])
  
  // If this payment was for a product, grant access
  if (p.product_id) {
    await db.query(`
      INSERT INTO user_product_access (id, user_id, product_id, payment_id, granted_at)
      VALUES (uuid_generate_v4(), $1, $2, $3, NOW())
      ON CONFLICT (user_id, product_id) DO NOTHING
    `, [p.user_id, p.product_id, p.id])
  }
  
  // Audit log
  await db.auditLogs.create({
    actor_type: 'stripe',
    action: 'payment.succeeded',
    resource_type: 'payment',
    resource_id: p.id,
    metadata: { amount_cents: paymentIntent.amount, stripe_payment_intent_id: paymentIntent.id }
  })
}


export async function onSubscriptionUpdated(stripeSubscription) {
  // Sync the subscription status from Stripe to our DB
  await db.query(`
    UPDATE subscriptions
    SET
      status = $1,
      current_period_start = to_timestamp($2),
      current_period_end = to_timestamp($3),
      cancel_at_period_end = $4,
      canceled_at = CASE WHEN $5::bigint IS NOT NULL THEN to_timestamp($5) ELSE canceled_at END,
      updated_at = NOW()
    WHERE stripe_subscription_id = $6
  `, [
    stripeSubscription.status,
    stripeSubscription.current_period_start,
    stripeSubscription.current_period_end,
    stripeSubscription.cancel_at_period_end,
    stripeSubscription.canceled_at,
    stripeSubscription.id,
  ])
  
  console.log(`Subscription ${stripeSubscription.id} updated to status: ${stripeSubscription.status}`)
}


export async function onSubscriptionDeleted(stripeSubscription) {
  // Subscription was fully canceled (not just marked cancel_at_period_end)
  await db.query(`
    UPDATE subscriptions
    SET status = 'canceled', canceled_at = NOW(), updated_at = NOW()
    WHERE stripe_subscription_id = $1
  `, [stripeSubscription.id])
  
  // Find the user and log
  const sub = await db.query(`
    SELECT user_id FROM subscriptions WHERE stripe_subscription_id = $1
  `, [stripeSubscription.id])
  
  if (sub.rows.length) {
    await db.auditLogs.create({
      actor_type: 'stripe',
      action: 'subscription.canceled',
      resource_type: 'subscription',
      resource_id: stripeSubscription.id,
      metadata: { reason: stripeSubscription.cancellation_details?.reason }
    })
  }
}


export async function onInvoicePaid(invoice) {
  // A subscription invoice was paid — update subscription status to active
  if (!invoice.subscription) return  // One-time invoice, not a subscription
  
  await db.query(`
    UPDATE subscriptions
    SET status = 'active', updated_at = NOW()
    WHERE stripe_subscription_id = $1
  `, [invoice.subscription])
  
  // Create an invoice record in our DB
  const sub = await db.query(`
    SELECT id, user_id FROM subscriptions WHERE stripe_subscription_id = $1
  `, [invoice.subscription])
  
  if (!sub.rows.length) return
  
  await db.query(`
    INSERT INTO invoices (id, user_id, subscription_id, stripe_invoice_id, amount_cents, status, paid_at)
    VALUES (uuid_generate_v4(), $1, $2, $3, $4, 'paid', NOW())
    ON CONFLICT (stripe_invoice_id) DO UPDATE
      SET status = 'paid', paid_at = NOW()
  `, [sub.rows[0].user_id, sub.rows[0].id, invoice.id, invoice.amount_paid])
}


export async function onInvoicePaymentFailed(invoice) {
  if (!invoice.subscription) return
  
  // Stripe will retry automatically — update status to past_due
  await db.query(`
    UPDATE subscriptions
    SET status = 'past_due', updated_at = NOW()
    WHERE stripe_subscription_id = $1
  `, [invoice.subscription])
  
  // Queue a "payment failed" email to the user
  const sub = await db.query(`
    SELECT s.user_id, u.email, u.display_name
    FROM subscriptions s
    JOIN users u ON u.id = s.user_id
    WHERE s.stripe_subscription_id = $1
  `, [invoice.subscription])
  
  if (sub.rows.length) {
    await emailQueue.add('payment-failed', {
      email: sub.rows[0].email,
      display_name: sub.rows[0].display_name,
      next_attempt: new Date(invoice.next_payment_attempt * 1000),
    })
  }
}


export async function onTrialWillEnd(stripeSubscription) {
  const sub = await db.query(`
    SELECT s.*, u.email, u.display_name
    FROM subscriptions s
    JOIN users u ON u.id = s.user_id
    WHERE s.stripe_subscription_id = $1
  `, [stripeSubscription.id])
  
  if (!sub.rows.length) return
  
  // Queue trial-ending email (sent 3 days before trial ends — Stripe triggers this at exactly that time)
  await emailQueue.add('trial-ending', {
    email: sub.rows[0].email,
    display_name: sub.rows[0].display_name,
    trial_ends_at: new Date(stripeSubscription.trial_end * 1000),
  })
}
```

## Testing Webhooks Locally

Stripe webhooks need a public URL. In local development, your server isn't publicly accessible. Use the Stripe CLI to forward events to your local server:

```bash
# Install Stripe CLI (https://stripe.com/docs/stripe-cli)
stripe login

# Forward all webhook events to your local server
stripe listen --forward-to http://localhost:3000/api/v1/webhooks/stripe

# In another terminal, trigger a specific event for testing
stripe trigger payment_intent.succeeded
stripe trigger customer.subscription.updated
stripe trigger customer.subscription.trial_will_end
```

The Stripe CLI:
1. Connects to Stripe with your account credentials
2. Receives all webhook events in real time
3. Forwards them to your local URL
4. Prints the signing secret (add this to your `.env` as `STRIPE_WEBHOOK_SECRET`)

## Why You Must NEVER Return a 5xx to Stripe

If your webhook handler returns a 5xx status, Stripe treats it as a failure and retries.

Stripe will retry with exponential backoff over several days. If your handler keeps failing:
- Stripe sends you retry notifications
- After 72+ hours of failures, Stripe disables the webhook endpoint
- You miss critical payment events

**The correct pattern:**
- Signature verification fails → return `400` (not a valid Stripe request)
- Any processing error → return `200`, log the error internally, monitor your logs

Stripe doesn't care about your internal errors. It just needs to know you received the event. Handle your errors with logging and alerting, not with Stripe status codes.

## The Idempotency Guarantee

Look at the `processWebhookEvent` function again:

```javascript
const existing = await db.query(`
  SELECT id, processed_at FROM webhook_events WHERE stripe_event_id = $1
`, [event.id])

if (existing.rows.length && existing.rows[0].processed_at) {
  return  // Already processed
}
```

This check + the `UNIQUE` constraint on `stripe_event_id` in the database means:
- First time the event arrives: process it, mark it processed
- Second time the same event arrives: skip it (already processed)
- Concurrent arrivals: database UNIQUE constraint prevents double insertion

This is idempotency. The same event processed twice produces the same result as processing it once.

This is non-negotiable in billing systems. Processing a payment twice = charging a customer twice = a very bad day.
