# Lesson 5.6 — Free Trials

## How Trials Work in Stripe

A free trial in Stripe is a period at the start of a subscription where no payment is collected. During the trial, the subscription status is `trialing`. When the trial ends, Stripe attempts the first payment and the status changes to `active` (if payment succeeds) or `past_due` / `incomplete` (if it fails).

## Setting Up a Trial at Subscription Creation

```javascript
const stripeSubscription = await stripe.subscriptions.create({
  customer: stripe_customer_id,
  items: [{ price: stripe_price_id }],
  trial_period_days: config.features.trialDays,  // e.g., 14
  // Or use trial_end for an exact timestamp:
  // trial_end: Math.floor(Date.now() / 1000) + (14 * 24 * 60 * 60)
})
```

Store locally:
```javascript
await db.query(`
  INSERT INTO subscriptions (..., status, trial_ends_at, ...)
  VALUES (..., 'trialing', to_timestamp($1), ...)
`, [stripeSubscription.trial_end])
```

## The Trial-Ending Warning (3 Days Before)

Stripe fires `customer.subscription.trial_will_end` exactly 3 days before the trial ends. This is your signal to send a warning email.

```javascript
// In webhooks.js
case 'customer.subscription.trial_will_end':
  await onTrialWillEnd(event.data.object)
  break

// Handler
export async function onTrialWillEnd(stripeSubscription) {
  const sub = await db.query(`
    SELECT s.id, s.plan_id, u.id as user_id, u.email, u.display_name,
           p.name as plan_name, pr.amount_cents
    FROM subscriptions s
    JOIN users u ON u.id = s.user_id
    JOIN plans p ON p.id = s.plan_id
    JOIN prices pr ON pr.id = s.locked_price_id
    WHERE s.stripe_subscription_id = $1
  `, [stripeSubscription.id])
  
  if (!sub.rows.length) return
  
  const { email, display_name, plan_name, amount_cents } = sub.rows[0]
  
  await emailService.send({
    to: email,
    template: 'trial-ending',
    data: {
      display_name,
      plan_name,
      amount_cents,
      trial_ends_at: new Date(stripeSubscription.trial_end * 1000),
      billing_date: new Date(stripeSubscription.trial_end * 1000),
    }
  })
}
```

## Restricting Access When Trial Expires

The `requireActiveSubscription` middleware from Lesson 3.2 handles this:

```javascript
const ACCESS_STATUSES = ['active', 'trialing']

if (!ACCESS_STATUSES.includes(subscription.status)) {
  return res.status(403).json({
    error: {
      code: 'SUBSCRIPTION_REQUIRED',
      message: 'Your trial has ended. Subscribe to continue access.',
      subscription_status: subscription.status,
    }
  })
}
```

The frontend reads `subscription_status` in the error and shows the appropriate message: "Trial ended" vs "Subscription canceled" vs "Payment failed."

## Feature Flag for Trials

The `.env.example` has:
```bash
FEATURE_TRIALS_ENABLED=true
TRIAL_DAYS=14
```

In code:
```javascript
trial_period_days: config.features.trialsEnabled
  ? config.features.trialDays
  : undefined
```

To disable trials globally: set `FEATURE_TRIALS_ENABLED=false`. No code change needed.

To offer different trial lengths per plan: add a `trial_days` column to the `plans` table and use `plan.trial_days ?? config.features.trialDays`.

## One Trial Per User (Preventing Abuse)

Users shouldn't be able to cancel, re-subscribe, and get a new trial each time.

Enforce in subscription creation:
```javascript
// Check if user has had a trial before
const hadTrial = await db.query(`
  SELECT id FROM subscriptions
  WHERE user_id = $1 AND trial_ends_at IS NOT NULL
  LIMIT 1
`, [user.id])

const offerTrial = config.features.trialsEnabled && !hadTrial.rows.length
```

Only offer a trial on the first subscription. Subsequent subscriptions skip the trial.
