# Lesson 6.4 — Seeding for Tests

## Why Test Seeds Must Be Deterministic

A **deterministic** test seed produces the same data every time it runs. Same emails, same subscription states, same coupon codes.

Why this matters: your tests reference specific users by email (`'admin@test.com'`), specific subscription states, specific coupon codes. If the seed is random or changes between runs, your tests break randomly — the most maddening kind of test failure.

## Test Database Strategy

Never run tests against your development database. Use a separate test database:

```bash
# In .env (not .env.example — this is your local secret)
DATABASE_TEST_URL=postgres://postgres:password@localhost:5432/saas_test
```

Before each test suite runs, reset the test database to a known state:

```javascript
// tests/helpers/db.js
import { db } from '../../src/db/index.js'

export async function resetDatabase() {
  // Truncate all tables in reverse dependency order (to avoid FK violations)
  await db.query(`
    TRUNCATE TABLE
      audit_logs,
      webhook_events,
      coupon_redemptions,
      payments,
      invoices,
      subscriptions,
      user_roles,
      users,
      prices,
      coupons
      -- Don't truncate roles, permissions, role_permissions, products, plans
      -- Those are seeded separately and don't change between tests
    RESTART IDENTITY CASCADE
  `)
}

export async function seedTestData() {
  // Run the test seed files
  await import('../../src/db/seeds/test/01-users.js').then(m => m.seed(db))
  await import('../../src/db/seeds/test/02-subscriptions.js').then(m => m.seed(db))
}
```

```javascript
// In your test setup (jest.config.js or setup file)
import { resetDatabase, seedTestData } from './helpers/db.js'

beforeAll(async () => {
  // Run required seeds (roles, permissions) once
  await runRequiredSeeds()
})

beforeEach(async () => {
  // Reset test data before each test
  await resetDatabase()
  await seedTestData()
})

afterAll(async () => {
  await db.end()
})
```

## The Test Seed Contract

Document the test seed as a contract that tests can rely on:

```javascript
// tests/TEST_SEED_CONTRACT.md
// (or in the test seed file itself)

/**
 * TEST SEED CONTRACT
 *
 * After running test seeds, the following data exists:
 *
 * Users:
 *   admin@test.com       / TestPassword123!  — role: admin, no subscription
 *   member@test.com      / TestPassword123!  — role: member, ACTIVE subscription (Monthly plan)
 *   member-trial@test.com/ TestPassword123!  — role: member, TRIALING subscription (7 days left)
 *   member-lapsed@test.com/TestPassword123!  — role: member, PAST_DUE subscription (grace expired)
 *   support@test.com     / TestPassword123!  — role: support, no subscription
 *
 * Products:
 *   'Digital Toolkit'    — $29.99, active
 *   'Business Bundle'    — $49.99, active
 *
 * Plans:
 *   'Monthly'    — $19.99/month
 *   'Quarterly'  — $49.99/3 months
 *   'Yearly'     — $179.99/year
 *
 * Coupons:
 *   'SAVE20'     — 20% off, unlimited uses, no expiry
 *   'FLAT10'     — $10 off, max 5 uses, no expiry
 *   'EXPIRED'    — 10% off, expired yesterday
 *   'MAXEDOUT'   — 15% off, max_uses = 1, current_uses = 1
 */
```

This contract is the foundation your integration tests build on. When a test fails, you check: "Is the seed data what I expect?" When you change the seed, you update the contract.

## Adding Coupon Test Data

```javascript
// tests/seeds/test/03-coupons.js
export async function seed(db) {
  await db.query(`
    INSERT INTO coupons (id, code, discount_type, discount_value, max_uses, expires_at, applies_to, is_active)
    VALUES
      (uuid_generate_v4(), 'SAVE20',   'percent', 20,  NULL, NULL,                    'all',  true),
      (uuid_generate_v4(), 'FLAT10',   'fixed',  1000, 5,    NULL,                    'all',  true),
      (uuid_generate_v4(), 'EXPIRED',  'percent', 10,  NULL, NOW() - INTERVAL '1 day', 'all', true),
      (uuid_generate_v4(), 'MAXEDOUT', 'percent', 15,  1,    NULL,                    'all',  true)
    ON CONFLICT (code) DO NOTHING
  `)
  
  // Set MAXEDOUT to max uses
  await db.query(`
    UPDATE coupons SET current_uses = 1 WHERE code = 'MAXEDOUT'
  `)
}
```

## The Complete Test for Coupon Validation

```javascript
describe('Coupon Validation', () => {
  const memberToken = () => loginAs('member@test.com')
  
  test('valid coupon returns correct discount', async () => {
    const token = await memberToken()
    const res = await request(app)
      .post('/api/v1/coupons/validate')
      .set('Authorization', `Bearer ${token}`)
      .send({ code: 'SAVE20', plan_id: monthlyPlanId })
    
    expect(res.status).toBe(200)
    expect(res.body.valid).toBe(true)
    expect(res.body.discount_type).toBe('percent')
    expect(res.body.discount_value).toBe(20)
  })
  
  test('expired coupon returns invalid', async () => {
    const token = await memberToken()
    const res = await request(app)
      .post('/api/v1/coupons/validate')
      .set('Authorization', `Bearer ${token}`)
      .send({ code: 'EXPIRED' })
    
    expect(res.body.valid).toBe(false)
    expect(res.body.reason).toBe('COUPON_EXPIRED')
  })
  
  test('maxed-out coupon returns invalid', async () => {
    const token = await memberToken()
    const res = await request(app)
      .post('/api/v1/coupons/validate')
      .set('Authorization', `Bearer ${token}`)
      .send({ code: 'MAXEDOUT' })
    
    expect(res.body.valid).toBe(false)
    expect(res.body.reason).toBe('COUPON_MAX_USES_REACHED')
  })
  
  test('nonexistent coupon returns invalid', async () => {
    const token = await memberToken()
    const res = await request(app)
      .post('/api/v1/coupons/validate')
      .set('Authorization', `Bearer ${token}`)
      .send({ code: 'DOESNOTEXIST' })
    
    expect(res.body.valid).toBe(false)
    expect(res.body.reason).toBe('COUPON_NOT_FOUND')
  })
})
```
