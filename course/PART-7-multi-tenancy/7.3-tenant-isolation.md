# Lesson 7.3 — Tenant Isolation in Every Query

## The Most Dangerous Bug in Multi-Tenant

Every database query on a tenant-scoped table must filter by `organization_id`. Always. Without exception.

This single rule, when broken, causes data breaches. Company A's subscriber sees Company B's invoices. It's not a theoretical risk — it happens.

**The goal:** make it structurally impossible (or at least extremely difficult) to forget the org filter.

---

## The Repository Pattern

A **repository** is a layer that wraps all database access for a specific entity. Instead of writing raw SQL everywhere, you call a function. The repository function always adds the org filter.

```javascript
// db/repositories/subscriptions.js

class SubscriptionRepository {
  constructor(db) {
    this.db = db
  }
  
  // ALWAYS takes organizationId as a required parameter
  async findById(id, organizationId) {
    const result = await this.db.query(`
      SELECT s.*, p.name as plan_name, pr.amount_cents
      FROM subscriptions s
      JOIN plans p ON p.id = s.plan_id
      JOIN prices pr ON pr.id = s.locked_price_id
      WHERE s.id = $1
        AND s.organization_id = $2     -- ← ALWAYS PRESENT
        AND s.deleted_at IS NULL
    `, [id, organizationId])
    
    return result.rows[0] ?? null
  }
  
  async findActiveByUserId(userId, organizationId) {
    const result = await this.db.query(`
      SELECT s.*, p.name as plan_name, pr.amount_cents, pr.currency
      FROM subscriptions s
      JOIN plans p ON p.id = s.plan_id
      JOIN prices pr ON pr.id = s.locked_price_id
      WHERE s.user_id = $1
        AND s.organization_id = $2     -- ← ALWAYS PRESENT
        AND s.status IN ('active', 'trialing', 'past_due')
        AND s.deleted_at IS NULL
      LIMIT 1
    `, [userId, organizationId])
    
    return result.rows[0] ?? null
  }
  
  async list(organizationId, { page = 1, perPage = 20 } = {}) {
    const offset = (page - 1) * perPage
    
    const result = await this.db.query(`
      SELECT s.*, u.email, u.display_name, p.name as plan_name, pr.amount_cents
      FROM subscriptions s
      JOIN users u ON u.id = s.user_id
      JOIN plans p ON p.id = s.plan_id
      JOIN prices pr ON pr.id = s.locked_price_id
      WHERE s.organization_id = $1     -- ← ALWAYS PRESENT
        AND s.deleted_at IS NULL
      ORDER BY s.created_at DESC
      LIMIT $2 OFFSET $3
    `, [organizationId, perPage, offset])
    
    const count = await this.db.query(`
      SELECT COUNT(*) FROM subscriptions
      WHERE organization_id = $1 AND deleted_at IS NULL
    `, [organizationId])
    
    return {
      subscriptions: result.rows,
      total: parseInt(count.rows[0].count),
      page,
      per_page: perPage,
    }
  }
  
  async create(data, organizationId) {
    const result = await this.db.query(`
      INSERT INTO subscriptions (
        id, user_id, organization_id, plan_id, locked_price_id,
        stripe_subscription_id, status, trial_ends_at,
        current_period_start, current_period_end
      )
      VALUES (uuid_generate_v4(), $1, $2, $3, $4, $5, $6, $7, $8, $9)
      RETURNING *
    `, [
      data.userId,
      organizationId,      // ← ALWAYS SET
      data.planId,
      data.lockedPriceId,
      data.stripeSubscriptionId,
      data.status,
      data.trialEndsAt,
      data.currentPeriodStart,
      data.currentPeriodEnd,
    ])
    
    return result.rows[0]
  }
}
```

Using the repository in a handler:

```javascript
// handlers/subscriptions.js

export async function getSubscription(req, res) {
  const { id } = req.params
  
  // req.organizationId is set by resolveOrganization middleware
  const subscription = await db.subscriptions.findById(id, req.organizationId)
  
  if (!subscription) {
    return res.status(404).json({ error: { code: 'NOT_FOUND', message: 'Subscription not found.' } })
  }
  
  return res.json({ subscription })
}
```

If a user from Org A requests a subscription that belongs to Org B:
- `findById(subId, orgA_id)` is called
- The query filters `WHERE id = subId AND organization_id = orgA_id`
- No rows returned → 404

The user gets "Not Found." They don't get 403 (which would confirm the resource exists). They don't get the resource. This is correct behavior.

## The Super-Admin Pattern

Some users need to access all tenants — platform administrators.

```javascript
// The super-admin can bypass org scoping
// Add a flag to the user or use a special role

export async function getSubscriptionAsAdmin(id) {
  // Super-admin query — NO org filter
  const result = await db.query(`
    SELECT s.*, u.email, o.name as org_name, p.name as plan_name
    FROM subscriptions s
    JOIN users u ON u.id = s.user_id
    JOIN organizations o ON o.id = s.organization_id
    JOIN plans p ON p.id = s.plan_id
    WHERE s.id = $1 AND s.deleted_at IS NULL
  `, [id])
  
  return result.rows[0]
}
```

Only use this in endpoints explicitly for super-admins, behind a strict role check:

```javascript
router.get('/admin/subscriptions/:id',
  authenticate,
  requireRole('super_admin'),      // Only super-admins
  getSubscriptionAsAdmin
)
```

Never expose the unscoped query through a regular user-accessible endpoint.

## Testing Tenant Isolation

This test is the most important test in a multi-tenant system:

```javascript
// tests/integration/tenant-isolation.test.js

describe('Tenant Isolation', () => {
  let orgAToken, orgBToken, orgASubId, orgBSubId
  
  beforeAll(async () => {
    // Set up two organizations with users and subscriptions
    // (use test seed or create in beforeAll)
    orgAToken = await loginAs('admin@org-a.test.com')
    orgBToken = await loginAs('admin@org-b.test.com')
    
    orgASubId = await getOrgSubscriptionId('org-a-id')
    orgBSubId = await getOrgSubscriptionId('org-b-id')
  })
  
  test('Org A cannot read Org B subscription', async () => {
    const res = await request(app)
      .get(`/api/v1/subscriptions/${orgBSubId}`)
      .set('Authorization', `Bearer ${orgAToken}`)
    
    // Should be 404 (not 403 — we don't even confirm the resource exists)
    expect(res.status).toBe(404)
  })
  
  test('Org B cannot read Org A subscription', async () => {
    const res = await request(app)
      .get(`/api/v1/subscriptions/${orgASubId}`)
      .set('Authorization', `Bearer ${orgBToken}`)
    
    expect(res.status).toBe(404)
  })
  
  test('Org A cannot list Org B subscriptions', async () => {
    const res = await request(app)
      .get('/api/v1/subscriptions')
      .set('Authorization', `Bearer ${orgAToken}`)
    
    expect(res.status).toBe(200)
    
    // None of the returned subscriptions should belong to Org B
    const orgBSubIds = res.body.subscriptions.map(s => s.id)
    expect(orgBSubIds).not.toContain(orgBSubId)
  })
  
  test('Org A user cannot modify Org B data', async () => {
    const res = await request(app)
      .patch(`/api/v1/subscriptions/${orgBSubId}/cancel`)
      .set('Authorization', `Bearer ${orgAToken}`)
    
    expect(res.status).toBe(404)
  })
})
```

This test suite should be run on every deployment. It's the regression test for the most critical security property in your system.
