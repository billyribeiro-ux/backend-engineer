# Lesson 8.1 — Audit Logging

## What an Audit Log Is

An audit log is an immutable, chronological record of every significant action taken in your system — who did it, what they did, when they did it, and what changed.

"Immutable" means: you never update or delete audit log entries. They're evidence. If you update them, they're worthless as evidence.

---

## Why You Need Audit Logs

**Billing disputes:** A customer says "I never canceled my subscription." Your audit log shows the exact timestamp and IP address of the cancellation. Case closed.

**Support investigations:** "Why is this user's price different?" Your audit log shows every price change, who made it, and what `applies_to` rule was used.

**Security incidents:** "Did someone access this account without authorization?" Your audit log shows every login, every failed login, every role change.

**Regulatory compliance:** Many regulated industries require audit trails. GDPR, HIPAA, SOC 2 — all have audit trail requirements.

---

## The Audit Log Table (Revisited)

```sql
audit_logs:
  id            UUID
  actor_id      UUID          -- user who did it (NULL for system actions)
  actor_type    TEXT          -- 'user', 'system', 'stripe'
  action        TEXT          -- 'subscription.canceled', 'price.updated', 'user.login'
  resource_type TEXT          -- 'subscription', 'price', 'user', etc.
  resource_id   UUID          -- UUID of the affected record
  organization_id UUID        -- which org this belongs to (nullable for platform actions)
  metadata      JSONB         -- context: old values, new values, IP, anything relevant
  ip_address    INET          -- for security audits
  created_at    TIMESTAMPTZ   -- NO updated_at, NO deleted_at
```

```javascript
  SUBSCRIPTION_CANCELED:       'subscription.canceled',
  SUBSCRIPTION_RESUMED:        'subscription.resumed',
  SUBSCRIPTION_PLAN_CHANGED:   'subscription.plan_changed',
  SUBSCRIPTION_STATUS_UPDATED: 'subscription.status_updated',
  
  // Prices
  PRICE_CREATED:   'price.created',
  PRICE_APPLIED:   'price.applied_to_members',
  
  // Payments
  PAYMENT_SUCCEEDED: 'payment.succeeded',
  PAYMENT_FAILED:    'payment.failed',
  PAYMENT_REFUNDED:  'payment.refunded',
  
  // Users
  USER_ROLE_CHANGED: 'user.role_changed',
  USER_INVITED:      'user.invited',
  
  // Coupons
  COUPON_CREATED:  'coupon.created',
  COUPON_USED:     'coupon.used',
  COUPON_EXPIRED:  'coupon.deactivated',
}

export async function log({
  actorId = null,
  actorType = 'user',
  action,
  resourceType,
  resourceId,
  organizationId = null,
  metadata = {},
  ipAddress = null,
}) {
  await db.query(`
    INSERT INTO audit_logs (
      id, actor_id, actor_type, action, resource_type, resource_id,
      organization_id, metadata, ip_address, created_at
    )
    VALUES (uuid_generate_v4(), $1, $2, $3, $4, $5, $6, $7, $8, NOW())
  `, [actorId, actorType, action, resourceType, resourceId, organizationId, JSON.stringify(metadata), ipAddress])
}

export { AUDIT_ACTIONS }
```

## What to Log

The rule: **log every action that has side effects on billing or access.**

Must log:
- All auth events (register, login, failed login, logout, password change)
- All subscription events (create, cancel, resume, plan change, status update)
- All payment events (succeeded, failed, refunded)
- All admin actions (price change, coupon create/deactivate, user role change)
- All access denied events for sensitive operations

Should log:
- User profile updates
- Organization member changes (invite, remove, role change)

Don't over-log:
- Every GET request (this creates noise that makes real events hard to find)
- Internal cron job runs (use a separate job log)

## The Audit Log Query API

```javascript
// handlers/admin.js

export async function getAuditLogs(req, res) {
  const {
    actor_id,
    resource_type,
    action,
    from,
    to,
    page = 1,
    per_page = 50,
  } = req.query
  
  const conditions = ['al.organization_id = $1']
  const params = [req.organizationId]
  let paramCount = 1
  
  if (actor_id) {
    conditions.push(`al.actor_id = $${++paramCount}`)
    params.push(actor_id)
  }
  if (resource_type) {
    conditions.push(`al.resource_type = $${++paramCount}`)
    params.push(resource_type)
  }
  if (action) {
    conditions.push(`al.action = $${++paramCount}`)
    params.push(action)
  }
  if (from) {
    conditions.push(`al.created_at >= $${++paramCount}`)
    params.push(new Date(from))
  }
  if (to) {
    conditions.push(`al.created_at <= $${++paramCount}`)
    params.push(new Date(to))
  }
  
  const offset = (page - 1) * per_page
  
  const result = await db.query(`
    SELECT
      al.*,
      u.email as actor_email,
      u.display_name as actor_name
    FROM audit_logs al
    LEFT JOIN users u ON u.id = al.actor_id
    WHERE ${conditions.join(' AND ')}
    ORDER BY al.created_at DESC
    LIMIT $${++paramCount} OFFSET $${++paramCount}
  `, [...params, per_page, offset])
  
  return res.json({
    logs: result.rows,
    page: parseInt(page),
    per_page: parseInt(per_page),
  })
}
```

Audit logs are queryable by:
- Who did it (`actor_id`)
- What type of thing was affected (`resource_type`)
- What happened (`action`)
- When (`from` / `to` date range)

This covers every reasonable support and compliance query.
