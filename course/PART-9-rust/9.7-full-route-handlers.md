# Lesson 9.7 — Full Route Handlers in Axum

## How Axum Routes Work

In Express, you register handlers like this:
```js
router.get('/users/me', authenticate, requirePermission('users:read'), async (req, res) => {
    // handler body
});
```

In Axum, you register handlers like this:
```rust
// in routes/mod.rs
Router::new()
    .route("/api/v1/users/me", get(users::get_me))
```

And the handler itself declares what it needs:
```rust
// in routes/users.rs
pub async fn get_me(
    auth: AuthUser,                    // ← requires authentication (extractor)
    State(state): State<AppState>,    // ← app state (database, config)
) -> Result<Json<UserResponse>, AppError> {
    // handler body
}
```

There is no explicit middleware chain per route. Each handler's parameter list is its contract: if it declares `AuthUser`, it requires authentication. If it declares `State(state)`, it needs app state. Axum runs all the extractors before calling the handler body.

## The Router — `src/routes/mod.rs`

```rust
use axum::{
    routing::{delete, get, post, put},
    Router,
};

use crate::state::AppState;

mod auth;
mod products;
mod subscriptions;
mod users;
pub mod webhooks;

pub fn create_router(state: AppState) -> Router {
    Router::new()
        // Health
        .route("/health", get(health_check))
        // Auth (no authentication required)
        .route("/api/v1/auth/register", post(auth::register))
        .route("/api/v1/auth/login", post(auth::login))
        .route("/api/v1/auth/refresh", post(auth::refresh))
        .route("/api/v1/auth/logout", post(auth::logout))
        // Users (requires AuthUser)
        .route("/api/v1/users/me", get(users::get_me).put(users::update_me))
        // Products
        .route("/api/v1/products", get(products::list).post(products::create))
        .route("/api/v1/products/:id", get(products::get_one).put(products::update))
        .route("/api/v1/products/:id/prices", post(products::add_price))
        // Subscriptions
        .route("/api/v1/subscriptions/me", get(subscriptions::get_mine))
        .route("/api/v1/subscriptions", get(subscriptions::list_all))
        .route("/api/v1/subscriptions/:id", get(subscriptions::get_one))
        .route("/api/v1/subscriptions", post(subscriptions::create))
        .route("/api/v1/subscriptions/me/cancel", post(subscriptions::cancel_mine))
        // Webhooks (no authentication — Stripe verifies with signature)
        .route("/api/v1/webhooks/stripe", post(webhooks::stripe_webhook))
        .with_state(state)
}

async fn health_check() -> axum::Json<serde_json::Value> {
    axum::Json(serde_json::json!({ "status": "ok" }))
}
```

`.with_state(state)` makes `AppState` available to all handlers via `State(state): State<AppState>` extraction. The state is cloned per request — `AppState` is `Clone`, and `PgPool` internally uses `Arc`, so cloning is cheap.

## Auth Handlers — `src/routes/auth.rs`

### Register

```rust
pub async fn register(
    State(state): State<AppState>,
    Json(body): Json<RegisterRequest>,
) -> Result<Json<AuthResponse>, AppError> {
    // Check for existing user
    let existing = sqlx::query!(
        "SELECT id FROM users WHERE email = $1",
        body.email
    )
    .fetch_optional(&state.db)
    .await
    .map_err(AppError::Internal)?;

    if existing.is_some() {
        return Err(AppError::bad_request(
            "EMAIL_EXISTS",
            "An account with this email already exists.",
        ));
    }

    // Hash password
    let password_hash = hash_password(&body.password)
        .map_err(|e| AppError::Internal(anyhow::anyhow!(e)))?;

    let user_id = Uuid::new_v4();

    // Create Stripe customer
    let customer = state
        .stripe
        .create_customer(&body.email, &user_id.to_string())
        .await?;
    let stripe_customer_id = customer["id"].as_str().unwrap_or("").to_string();

    // Insert user
    sqlx::query!(
        r#"
        INSERT INTO users (id, email, password_hash, display_name, role, stripe_customer_id)
        VALUES ($1, $2, $3, $4, 'member', $5)
        "#,
        user_id,
        body.email,
        password_hash,
        body.display_name,
        stripe_customer_id,
    )
    .execute(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Generate tokens and respond
    let access_token = generate_access_token(
        user_id,
        &body.email,
        "member",
        &state.config.jwt_secret,
        state.config.jwt_access_expiry_secs,
    )
    .map_err(|e| AppError::Internal(anyhow::anyhow!(e)))?;

    Ok(Json(AuthResponse {
        access_token,
        refresh_token: generate_refresh_token(...)?,
        user: UserResponse { id: user_id, email: body.email, ... },
    }))
}
```

**What happens when Stripe fails?** If `create_customer` returns an error, the user is never inserted into the database. The registration fails with a 500. The user can retry. No orphaned user records. This is intentional — you never want a user in your database without a Stripe customer ID.

### Refresh

```rust
pub async fn refresh(
    State(state): State<AppState>,
    Json(body): Json<RefreshTokenRequest>,
) -> Result<Json<RefreshResponse>, AppError> {
    // Verify the token
    let claims = verify_refresh_token(&body.refresh_token, &state.config.jwt_refresh_secret)
        .map_err(|_| AppError::bad_request("INVALID_TOKEN", "Invalid or expired refresh token."))?;

    let user_id = Uuid::parse_str(&claims.sub)
        .map_err(|_| AppError::bad_request("INVALID_TOKEN", "Invalid token subject."))?;

    // Check if token exists in DB (not revoked)
    let token_record = sqlx::query!(
        "SELECT id FROM refresh_tokens WHERE user_id = $1 AND token = $2 AND revoked_at IS NULL AND expires_at > NOW()",
        user_id,
        body.refresh_token,
    )
    .fetch_optional(&state.db)
    .await
    .map_err(AppError::Internal)?
    .ok_or_else(|| AppError::bad_request("INVALID_TOKEN", "Token has been revoked or expired."))?;

    // Revoke old token (rotation)
    sqlx::query!(
        "UPDATE refresh_tokens SET revoked_at = NOW() WHERE id = $1",
        token_record.id
    )
    .execute(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Fetch user to get current role
    let user = sqlx::query!(
        "SELECT id, email, role FROM users WHERE id = $1",
        user_id
    )
    .fetch_one(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Issue new tokens
    let new_access_token = generate_access_token(user.id, &user.email, &user.role, ...)?;
    let new_refresh_token = generate_refresh_token(user.id, ...)?;

    // Store new refresh token
    sqlx::query!(
        "INSERT INTO refresh_tokens (id, user_id, token, expires_at) VALUES (uuid_generate_v4(), $1, $2, NOW() + INTERVAL '30 days')",
        user_id,
        new_refresh_token,
    )
    .execute(&state.db)
    .await
    .map_err(AppError::Internal)?;

    Ok(Json(RefreshResponse {
        access_token: new_access_token,
        refresh_token: new_refresh_token,
    }))
}
```

Token rotation: the old refresh token is revoked, a new one is issued. If an attacker steals a refresh token and uses it, the legitimate user's next refresh will fail (token already revoked), alerting them that their session was compromised.

## Product Handlers — `src/routes/products.rs`

### List (Public)

```rust
pub async fn list(
    State(state): State<AppState>,
    optional_auth: OptionalAuthUser,
) -> Result<Json<Vec<ProductResponse>>, AppError> {
    let products = sqlx::query!(
        "SELECT id, name, description, is_active FROM products WHERE deleted_at IS NULL"
    )
    .fetch_all(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Map to response type
    let response: Vec<ProductResponse> = products
        .into_iter()
        .map(|p| ProductResponse {
            id: p.id,
            name: p.name,
            description: p.description,
            is_active: p.is_active,
        })
        .collect();

    Ok(Json(response))
}
```

`OptionalAuthUser` is used here because the product list is public — but if a user is logged in, you could show them their purchase history or lock icons on products they haven't bought.

### Create (Admin Only)

```rust
pub async fn create(
    auth: AuthUser,
    State(state): State<AppState>,
    Json(body): Json<CreateProductRequest>,
) -> Result<(StatusCode, Json<ProductResponse>), AppError> {
    // RBAC: only admins with products:write permission
    check_permission(&auth, "products:write", &state).await?;

    let product_id = Uuid::new_v4();

    // Sync to Stripe
    let stripe_product = state
        .stripe
        .create_product(&body.name, &product_id.to_string())
        .await?;
    let stripe_product_id = stripe_product["id"].as_str().unwrap_or("").to_string();

    // Insert into database
    sqlx::query!(
        r#"
        INSERT INTO products (id, name, description, stripe_product_id)
        VALUES ($1, $2, $3, $4)
        "#,
        product_id,
        body.name,
        body.description,
        stripe_product_id,
    )
    .execute(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Audit log
    sqlx::query!(
        r#"
        INSERT INTO audit_logs (id, actor_id, action, resource_type, resource_id, metadata)
        VALUES (uuid_generate_v4(), $1, 'product.created', 'product', $2, $3)
        "#,
        auth.id,
        product_id,
        serde_json::json!({ "name": body.name }),
    )
    .execute(&state.db)
    .await
    .map_err(AppError::Internal)?;

    Ok((
        StatusCode::CREATED,
        Json(ProductResponse { id: product_id, name: body.name, ... }),
    ))
}
```

Notice the return type: `(StatusCode, Json<ProductResponse>)`. Axum's `IntoResponse` allows returning a tuple of `(StatusCode, body)` to set a custom status code. The default for `Json<T>` is 200 OK; for resource creation you want 201 Created.

## Subscription Handlers — `src/routes/subscriptions.rs`

### Get My Subscription

```rust
pub async fn get_mine(
    auth: AuthUser,
    State(state): State<AppState>,
) -> Result<Json<Subscription>, AppError> {
    let subscription = sqlx::query_as!(
        Subscription,
        r#"
        SELECT s.*, p.amount_cents, p.currency, p.interval, p.interval_count
        FROM subscriptions s
        JOIN prices p ON s.price_id = p.id
        WHERE s.user_id = $1
          AND s.status != 'canceled'
        ORDER BY s.created_at DESC
        LIMIT 1
        "#,
        auth.id
    )
    .fetch_optional(&state.db)
    .await
    .map_err(AppError::Internal)?
    .ok_or(AppError::NotFound)?;

    Ok(Json(subscription))
}
```

The ABAC check is implicit here: `WHERE s.user_id = $1` where `$1` is `auth.id`. A user can only ever get back their own subscription. There's no way for User A to accidentally get User B's subscription because the query is always scoped to `auth.id`.

### Create Subscription

```rust
pub async fn create(
    auth: AuthUser,
    State(state): State<AppState>,
    Json(body): Json<CreateSubscriptionRequest>,
) -> Result<(StatusCode, Json<Subscription>), AppError> {
    // Get the user's Stripe customer ID
    let user = sqlx::query!(
        "SELECT stripe_customer_id FROM users WHERE id = $1",
        auth.id
    )
    .fetch_one(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Get the price
    let price = sqlx::query!(
        "SELECT id, stripe_price_id FROM prices WHERE id = $1 AND is_active = true",
        body.price_id
    )
    .fetch_optional(&state.db)
    .await
    .map_err(AppError::Internal)?
    .ok_or(AppError::bad_request("PRICE_NOT_FOUND", "The selected price is no longer available."))?;

    // Check if already subscribed
    let existing = sqlx::query!(
        "SELECT id FROM subscriptions WHERE user_id = $1 AND status IN ('active', 'trialing')",
        auth.id
    )
    .fetch_optional(&state.db)
    .await
    .map_err(AppError::Internal)?;

    if existing.is_some() {
        return Err(AppError::bad_request(
            "ALREADY_SUBSCRIBED",
            "You already have an active subscription.",
        ));
    }

    // Create Stripe subscription (with optional trial)
    let stripe_sub = state
        .stripe
        .create_subscription(
            &user.stripe_customer_id,
            &price.stripe_price_id,
            Some(14), // 14-day trial
        )
        .await?;

    let stripe_sub_id = stripe_sub["id"].as_str().unwrap_or("").to_string();
    let status = stripe_sub["status"].as_str().unwrap_or("trialing").to_string();
    let subscription_id = Uuid::new_v4();

    // Store subscription — lock in the price (grandfathering)
    sqlx::query!(
        r#"
        INSERT INTO subscriptions (
            id, user_id, price_id, locked_price_id, stripe_subscription_id,
            status, trial_ends_at
        )
        VALUES ($1, $2, $3, $3, $4, $5, NOW() + INTERVAL '14 days')
        "#,
        subscription_id,
        auth.id,
        price.id,            // price_id AND locked_price_id are the same at creation
        stripe_sub_id,
        status,
    )
    .execute(&state.db)
    .await
    .map_err(AppError::Internal)?;

    // Return subscription
    // ...
}
```

`locked_price_id` is set to `price.id` at subscription creation. When prices change in the future, `price_id` can be updated but `locked_price_id` stays the same — this is how grandfathering works. The user always pays the price they subscribed at.

## Error Types and `IntoResponse`

Every handler returns `Result<T, AppError>`. `AppError` converts to an HTTP response automatically because it implements `IntoResponse`:

```rust
// src/errors.rs
impl IntoResponse for AppError {
    fn into_response(self) -> axum::response::Response {
        let (status, code, message) = match &self {
            AppError::NotFound => (StatusCode::NOT_FOUND, "NOT_FOUND", "Resource not found."),
            AppError::Forbidden => (StatusCode::FORBIDDEN, "FORBIDDEN", "Access denied."),
            AppError::BadRequest { code, message } => {
                (StatusCode::BAD_REQUEST, code.as_str(), message.as_str())
            }
            AppError::Internal(e) => {
                tracing::error!("Internal error: {:?}", e);
                (StatusCode::INTERNAL_SERVER_ERROR, "INTERNAL_ERROR", "An internal error occurred.")
            }
        };

        (
            status,
            Json(json!({ "error": code, "message": message })),
        )
            .into_response()
    }
}
```

When `AppError::Internal` matches, the actual error is logged (with `tracing::error!`) but the client receives only `"An internal error occurred."`. The caller never sees database errors, file paths, or stack traces.

## The Request → Handler Flow

For a request like `PUT /api/v1/users/me`:

```
1. Request arrives
2. Axum matches route: users::update_me
3. Axum runs extractors in order:
   a. AuthUser::from_request_parts → reads Authorization header, verifies JWT, returns AuthUser (or 401)
   b. State<AppState> → pulls app state (always succeeds)
   c. Json<UpdateProfileRequest> → parses body JSON (or 422 if malformed)
4. If all extractors succeed → handler body runs
5. Handler returns Result<Json<UserResponse>, AppError>
6. AppError::IntoResponse converts errors to HTTP responses
7. Json<UserResponse> serializes to JSON with 200 OK
```

If step 3a fails (bad token) → Axum returns the extractor's rejection immediately. The handler body never executes. The developer doesn't need to write any error-handling code for the "not authenticated" case.

This is the architecture: **declare requirements, let the framework enforce them**.
