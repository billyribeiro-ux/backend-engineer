# Lesson 9.8 — Testing in Rust

## The Testing Pyramid in Rust

From Lesson 6.1, the pyramid:

```
         /\
        /  \    E2E (Stripe CLI + real server)
       /----\
      /      \  Integration (real DB, HTTP client)
     /--------\
    /          \ Unit (pure functions, no I/O)
   /------------\
```

In Rust, each layer has its own testing approach:

| Layer | Rust Mechanism | Command |
|-------|----------------|---------|
| Unit | `#[test]` or `#[cfg(test)]` | `cargo test --lib` |
| Integration | `#[tokio::test]` + test DB | `cargo test` |
| E2E | Stripe CLI + running server | manual / CI |

## Unit Tests: No Database, No Network

Unit tests in Rust live right next to the code they test, in a `#[cfg(test)]` block:

```rust
// src/policies/mod.rs

pub fn can_edit_profile(user: &AuthUser, target_user_id: Uuid, is_org_owner: bool) -> bool {
    if user.id == target_user_id { return true; }
    if user.role == "admin" && !is_org_owner { return true; }
    false
}

pub fn apply_discount(amount_cents: i64, coupon: &Coupon) -> i64 {
    match coupon.discount_type.as_str() {
        "percent" => amount_cents - (amount_cents * coupon.discount_value as i64 / 100),
        "fixed"   => (amount_cents - coupon.discount_value as i64 * 100).max(0),
        _         => amount_cents,
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    fn member(id: Uuid) -> AuthUser {
        AuthUser { id, email: "m@test.com".into(), role: "member".into(), organization_id: None }
    }

    fn admin(id: Uuid) -> AuthUser {
        AuthUser { id, email: "a@test.com".into(), role: "admin".into(), organization_id: None }
    }

    // ---- ABAC policy tests ----

    #[test]
    fn member_can_edit_own_profile() {
        let id = Uuid::new_v4();
        assert!(can_edit_profile(&member(id), id, false));
    }

    #[test]
    fn member_cannot_edit_other_profile() {
        let user = member(Uuid::new_v4());
        assert!(!can_edit_profile(&user, Uuid::new_v4(), false));
    }

    #[test]
    fn admin_can_edit_non_owner_profile() {
        let admin = admin(Uuid::new_v4());
        assert!(can_edit_profile(&admin, Uuid::new_v4(), false));
    }

    #[test]
    fn admin_cannot_edit_org_owner_profile() {
        let admin = admin(Uuid::new_v4());
        assert!(!can_edit_profile(&admin, Uuid::new_v4(), true));
    }

    // ---- Coupon discount tests ----

    fn percent_coupon(pct: i32) -> Coupon {
        Coupon { discount_type: "percent".into(), discount_value: pct, ..Default::default() }
    }

    fn fixed_coupon(dollars: i32) -> Coupon {
        Coupon { discount_type: "fixed".into(), discount_value: dollars, ..Default::default() }
    }

    #[test]
    fn percent_discount_applied_correctly() {
        // $29.00 with 20% off = $23.20
        assert_eq!(apply_discount(2900, &percent_coupon(20)), 2320);
    }

    #[test]
    fn fixed_discount_applied_correctly() {
        // $29.00 with $5.00 off = $24.00
        assert_eq!(apply_discount(2900, &fixed_coupon(5)), 2400);
    }

    #[test]
    fn fixed_discount_cannot_go_negative() {
        // $2.00 with $10.00 off = $0.00 (not -$8.00)
        assert_eq!(apply_discount(200, &fixed_coupon(10)), 0);
    }
}
```

Run only unit tests (fast — no DB needed):
```bash
cargo test --lib
```

Run with output visible:
```bash
cargo test --lib -- --nocapture
```

## Integration Tests: With a Real Database

Integration tests live in the `tests/` directory (separate from `src/`):

```
tests/
├── helpers.rs     — shared setup: test server, test DB, seed data
└── auth_test.rs   — integration tests for auth endpoints
```

### The Test Helper — `tests/helpers.rs`

```rust
use axum_test::TestServer;
use sqlx::PgPool;
use uuid::Uuid;

use saas_backend::{config::Config, routes::create_router, state::AppState, services::stripe::StripeClient};

pub async fn create_test_server() -> TestServer {
    // Load .env.test or fall back to environment
    dotenvy::from_filename(".env.test").ok();
    dotenvy::dotenv().ok();

    let config = Config::from_env().expect("Failed to load config");

    // Connect to the test database (must be separate from dev DB)
    let db = PgPool::connect(&config.database_url)
        .await
        .expect("Failed to connect to test database");

    // Run migrations
    sqlx::migrate!("./migrations")
        .run(&db)
        .await
        .expect("Failed to run migrations");

    // Clean the database for this test run
    reset_database(&db).await;

    let stripe = StripeClient::new(&config);
    let state = AppState { db, config, stripe };
    let router = create_router(state);

    TestServer::new(router).expect("Failed to create test server")
}

async fn reset_database(db: &PgPool) {
    // Order matters — children before parents (foreign key constraints)
    sqlx::query!("TRUNCATE TABLE audit_logs CASCADE").execute(db).await.unwrap();
    sqlx::query!("TRUNCATE TABLE webhook_events CASCADE").execute(db).await.unwrap();
    sqlx::query!("TRUNCATE TABLE refresh_tokens CASCADE").execute(db).await.unwrap();
    sqlx::query!("TRUNCATE TABLE subscriptions CASCADE").execute(db).await.unwrap();
    sqlx::query!("TRUNCATE TABLE coupon_redemptions CASCADE").execute(db).await.unwrap();
    sqlx::query!("TRUNCATE TABLE users CASCADE").execute(db).await.unwrap();
    // Don't truncate roles, permissions, role_permissions — they're seeded constants
}
```

### Auth Integration Tests — `tests/auth_test.rs`

```rust
mod helpers;
use serde_json::json;

#[tokio::test]
async fn test_register_and_login() {
    let server = helpers::create_test_server().await;

    // Register
    let response = server
        .post("/api/v1/auth/register")
        .json(&json!({
            "email": "test@example.com",
            "password": "SecurePass123!",
            "display_name": "Test User"
        }))
        .await;

    response.assert_status_created();
    let body = response.json::<serde_json::Value>();
    assert!(body["access_token"].is_string(), "access_token must be present");
    assert_eq!(body["user"]["email"], "test@example.com");
    assert_eq!(body["user"]["role"], "member");

    // Login with same credentials
    let login_response = server
        .post("/api/v1/auth/login")
        .json(&json!({
            "email": "test@example.com",
            "password": "SecurePass123!"
        }))
        .await;

    login_response.assert_status_ok();
    let login_body = login_response.json::<serde_json::Value>();
    assert!(login_body["access_token"].is_string());
}

#[tokio::test]
async fn test_login_with_wrong_password() {
    let server = helpers::create_test_server().await;

    // Register first
    server
        .post("/api/v1/auth/register")
        .json(&json!({
            "email": "user@example.com",
            "password": "CorrectPass123!",
            "display_name": "Test"
        }))
        .await;

    // Login with wrong password
    let response = server
        .post("/api/v1/auth/login")
        .json(&json!({
            "email": "user@example.com",
            "password": "WrongPass123!"
        }))
        .await;

    response.assert_status_bad_request();
    let body = response.json::<serde_json::Value>();
    assert_eq!(body["error"], "INVALID_CREDENTIALS");
}

#[tokio::test]
async fn test_login_with_nonexistent_email() {
    let server = helpers::create_test_server().await;

    let response = server
        .post("/api/v1/auth/login")
        .json(&json!({
            "email": "nobody@example.com",
            "password": "AnyPass123!"
        }))
        .await;

    // Same error as wrong password — user enumeration prevention
    response.assert_status_bad_request();
    let body = response.json::<serde_json::Value>();
    assert_eq!(body["error"], "INVALID_CREDENTIALS");
}

#[tokio::test]
async fn test_protected_route_without_token() {
    let server = helpers::create_test_server().await;

    let response = server.get("/api/v1/users/me").await;

    response.assert_status_unauthorized();
}

#[tokio::test]
async fn test_protected_route_with_valid_token() {
    let server = helpers::create_test_server().await;

    // Register to get a token
    let register_response = server
        .post("/api/v1/auth/register")
        .json(&json!({
            "email": "auth_test@example.com",
            "password": "SecurePass123!",
            "display_name": "Auth Test"
        }))
        .await;

    let token = register_response.json::<serde_json::Value>()["access_token"]
        .as_str()
        .unwrap()
        .to_string();

    // Access protected route
    let me_response = server
        .get("/api/v1/users/me")
        .add_header("Authorization", format!("Bearer {}", token))
        .await;

    me_response.assert_status_ok();
    let body = me_response.json::<serde_json::Value>();
    assert_eq!(body["email"], "auth_test@example.com");
}
```

```rust
async fn test_admin_can_create_product() {
```

## Testing Webhook Idempotency

This test sends the same webhook event twice and verifies it's only processed once:

## Testing Grandfathering

```rust
#[tokio::test]
async fn test_grandfathered_user_pays_old_price() {
    let db = helpers::get_test_db().await;

    let product_id = Uuid::new_v4();
    let old_price_id = Uuid::new_v4();
    let new_price_id = Uuid::new_v4();

    // Create product with original price
    sqlx::query!(
        "INSERT INTO products (id, name) VALUES ($1, 'Pro Plan')",
        product_id
    ).execute(&db).await.unwrap();

    sqlx::query!(
        "INSERT INTO prices (id, product_id, amount_cents, is_active) VALUES ($1, $2, 2900, false)",
        old_price_id, product_id
    ).execute(&db).await.unwrap();

    sqlx::query!(
        "INSERT INTO prices (id, product_id, amount_cents, is_active) VALUES ($1, $2, 3900, true)",
        new_price_id, product_id
    ).execute(&db).await.unwrap();

    // User subscribed at the old price
    let user_id = Uuid::new_v4();
    sqlx::query!(
        r#"INSERT INTO subscriptions
           (id, user_id, price_id, locked_price_id, status)
           VALUES ($1, $2, $3, $4, 'active')"#,
        Uuid::new_v4(), user_id, new_price_id, old_price_id // locked to old!
    ).execute(&db).await.unwrap();

    // Query what this user actually pays
    let result = sqlx::query!(
        r#"
        SELECT p.amount_cents
        FROM subscriptions s
        JOIN prices p ON s.locked_price_id = p.id
        WHERE s.user_id = $1 AND s.status = 'active'
        "#,
        user_id
    )
    .fetch_one(&db)
    .await
    .unwrap();

    assert_eq!(result.amount_cents, 2900); // old price, not 3900
}
```

## Running Tests

```bash
# All tests (unit + integration)
cargo test

# Unit tests only (fast, no DB)
cargo test --lib

# Integration tests only
cargo test --test '*'

# Specific test by name
cargo test test_register_and_login

# With output
cargo test -- --nocapture

# With environment
DATABASE_URL=postgres://postgres:password@localhost:5432/saas_test cargo test
```

### `.env.test`

Create a `.env.test` file for test configuration:

```env
DATABASE_URL=postgres://postgres:password@localhost:5432/saas_test
JWT_SECRET=test-jwt-secret-not-for-production
JWT_REFRESH_SECRET=test-refresh-secret-not-for-production
STRIPE_SECRET_KEY=sk_test_your_test_key
STRIPE_WEBHOOK_SECRET=whsec_test_your_webhook_secret
```

The test helper loads this file first, so tests always use the test database — never your development database.

## What the Tests Prove

| Test | What It Verifies |
|------|-----------------|
| `test_register_and_login` | Full auth flow works end-to-end |
| `test_login_with_wrong_password` | Wrong credentials are rejected |
| `test_login_with_nonexistent_email` | Same error for nonexistent email (no enumeration) |
| `test_protected_route_without_token` | Unauthenticated requests get 401 |
| `test_member_cannot_create_product` | RBAC enforcement works |
| `test_admin_can_create_product` | Admin permissions work |
| `test_user_cannot_edit_other_users_profile` | ABAC ownership check works |
| `test_webhook_idempotency` | Same event processed only once |
| `test_grandfathered_user_pays_old_price` | Price locking works correctly |

When `cargo test` passes all of these, the system behaves correctly for the critical paths. The next layer — E2E with real Stripe webhooks via the Stripe CLI — validates the integration with the external system.
